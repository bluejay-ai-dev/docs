## Lesson summary

Running tests manually is fine when you are getting started, but as your agent matures you will want testing and monitoring to happen on autopilot. This topic covers Schedules (recurring simulation runs), CI/CD integration, webhooks, and the voice provider and transport integrations that connect Bluejay to your production stack.

## Objectives

- Schedule a simulation to run on a recurring basis
- React to results automatically with webhooks and alerts
- Understand how to integrate Bluejay into a CI/CD pipeline
- Connect voice provider and simulation transport integrations

## Walkthrough

<Steps titleSize="h3">
  <Step title="Set up a Schedule">
    A **Schedule** makes a simulation run automatically at a regular interval, so your test suite keeps running without anyone clicking Run.

    Common schedules:
    - **Daily at 9 AM** — Run your regression suite every morning before the team starts work
    - **Hourly** — Continuously exercise a high-traffic agent
    - **Weekly on Monday** — Run a full test plan at the start of each sprint

    To create a Schedule, open the simulation you want to automate, add a schedule, and pick a frequency (every N minutes or hours, daily, weekly, monthly, or a raw cron expression).
  </Step>
  <Step title="React to results automatically">
    Two features close the loop on scheduled runs:

    - **Webhooks** — Bluejay POSTs to your endpoint when results are evaluated or runs finish, so your own systems can react. See [Webhooks](/key-concepts/webhooks/overview).
    - **Alerts** — Fire a Slack message or notification when a metric crosses a threshold, like a pass rate dropping below 80%. See [Alerts](/key-concepts/alerts/overview).

    Together with Schedules, this gives you the automated pipeline: run every morning, score every call, and get pinged only when something regresses.
  </Step>
  <Step title="Integrate with CI/CD">
    You can trigger Bluejay simulations from your CI/CD pipeline so every code change gets tested automatically. The pattern:

    1. Your pipeline deploys a new version of your agent
    2. A script calls the Bluejay API to queue a simulation run
    3. The script polls for results (or uses a webhook to wait)
    4. If metrics pass, the pipeline continues; if they fail, it blocks the deploy

    Bluejay provides a [GitHub Actions cookbook](/cookbook/github-actions) with ready-to-use workflow examples. The same approach works with any CI system that can make HTTP requests.
  </Step>
  <Step title="Connect voice provider integrations">
    If your agent runs on a third-party voice provider, you can connect it to Bluejay for automatic observability (production call scoring) and simulation transport.

    **Observability integrations** (production monitoring):

    | Provider | How to connect |
    |---|---|
    | **Retell** | Add your Bluejay org API key + Retell webhook URL. [Guide →](/integrations/retell) |
    | **Vapi** | Add your Bluejay org API key + server URL. [Guide →](/integrations/vapi) |
    | **Bland** | Add your webhook secret + inbound URL. [Guide →](/integrations/bland) |
    | **ElevenLabs** | Add your webhook + Provider ID. [Guide →](/integrations/eleven-labs) |

    **Simulation transport integrations** (how Bluejay calls your agent during tests):

    | Transport | When to use it |
    |---|---|
    | [Telephony](/simulation-integrations/telephony) | Standard phone calls (PSTN) |
    | [SIP](/simulation-integrations/sip) | SIP trunking (recommended for phone-based agents) |
    | [LiveKit](/simulation-integrations/livekit) | WebRTC voice via LiveKit |
    | [WebSockets](/simulation-integrations/websockets) | Streaming text or audio (CHIRP protocol) |
    | [HTTP Webhooks](/simulation-integrations/http-webhooks) | Request/response chat agents |
    | [Pipecat](/simulation-integrations/pipecat) | Pipecat Cloud agents |

    Each guide walks you through the connection step by step. Most take under ten minutes to set up.
  </Step>
</Steps>

## Knowledge check

<AccordionGroup>
  <Accordion title="When would you use a Schedule?">
    Use a Schedule when you want a simulation to run automatically at regular intervals — for example, running your regression suite every morning or exercising a high-traffic agent hourly.
  </Accordion>
  <Accordion title="How do you get notified when a scheduled run regresses?">
    Create an alert on the metric you care about (like pass rate) and route it to Slack, or subscribe a webhook to result events so your own systems can react.
  </Accordion>
  <Accordion title="How do you integrate Bluejay into a CI/CD pipeline?">
    Your pipeline calls the Bluejay API to queue a simulation run after deploying a new agent version. It then waits for results (via polling or webhooks). If the metrics pass, the deploy continues; if they fail, the pipeline blocks. The GitHub Actions cookbook has ready-to-use examples.
  </Accordion>
</AccordionGroup>
