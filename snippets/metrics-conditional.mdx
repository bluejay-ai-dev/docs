Use a conditional metric when a rule applies only to some conversations. For example, check the refund policy wording only when the agent called the refund tool. On other conversations, the metric does not run and has no result.

A condition can check that:

- The conversation reached a node of the agent [workflow](/test/simulations/reference#workflow). You pick the node from the workflow, so the metric must grade one agent. In YAML, find node IDs with [Get Workflow Summary](/api-reference/endpoint/get-workflow-summary).
- The agent called a given tool.
- Another metric has a given result, for example Fail.

A condition can read only metrics that always run. In YAML, see the [conditional metric example](/bluejay-as-code/cookbook#conditional-metrics).
