A Digital Human is one test case: a simulated customer that calls, texts, or emails your agent with a goal, and the checks that decide whether your agent handled it. Give it [personas](/test/simulations/personas) to run the same test with different callers.

## Bring your test cases

If you already have test cases in a spreadsheet, upload them: each row becomes a Digital Human, with no AI planning or rewriting. See [Upload CSV](/test/simulation-types/upload-digital-humans). Your test cases are listed on the **Test Cases** tab of the **Digital Humans** page.

You can also ask a [simulation plan](/test/simulations/create) to write them, write one by hand, or use the [API](/api-reference/endpoint/create-digital-humans), the [MCP tools](/mcp/testing-tools#digital-humans) or [Bluejay as Code](/bluejay-as-code/overview).

## Runs as

A Digital Human runs once as each persona it lists. With no personas, it runs once as the baseline: its own settings.

| Personas | Conversations per run |
|---|---|
| None | 1, as the Digital Human itself |
| Rushed commuter, Careful retiree | 2, one as each persona |

- Set them on the Digital Human's **Persona** tab, or for many Digital Humans at once with bulk edit.
- A persona replaces the caller fields it sets, such as voice, background noise and personality description. Everything else, including the intent and success criteria, comes from the Digital Human, so every call tests the same goal.
- An edit to a persona changes every Digital Human that runs as it, from the next run on.
- A [customer journey](/test/simulation-types/customer-journeys) always runs as the baseline.

## Settings

| Setting | Write |
|---|---|
| Description / Intent | What the caller wants, in one or two sentences. |
| Success Criteria | Agent outcomes the transcript can show, one per bullet. See [Success criteria](#success-criteria). |
| Personality | Who the caller is, in one short line, when the Digital Human runs as the baseline. |
| Scripted Responses | Fixed replies to specific agent lines. See [Scripted responses](/test/simulations/personas#scripted-responses). |
| Tool Adherence | The tool calls the agent must make. |
| Traits | Facts the caller gives when asked. See [Traits](#traits). |
| Tool Response Overrides | What each tool returns in this Digital Human's runs when **Mock tool calls** is on for the agent. An override replaces the agent's mode for that tool; leave it empty to use the agent's mode. See [Mock tool calls](/test/simulations/mock-tools). |

## Success criteria

Bluejay grades each bullet on its own. A conversation passes only when every bullet passes, so a call that meets three of four bullets fails with a 75% pass rate.

- To correct a grade, override the one bullet that is wrong. The conversation's pass or fail follows it.
- When you change the bullets, later conversations are graded against the new list. Past conversations keep their grades.
- In the API, `/v1` reads and writes success criteria as one string with a bullet per line. The grade of each bullet and `criteria_pass_rate` are on [`/v2` retrieve](/api-reference/endpoint/retrieve-simulation-results-v2).

## Traits

A trait is a fact that the caller knows and says when the agent asks, for example a member ID or date of birth. Use a trait when the value must be the same on each run. If you write the value in the intent instead, the caller can say a different value on each run.

Add a trait and its value on each Digital Human. A trait can also go out as a SIP header on the call, named after the trait with an `X-` prefix.

When you change a trait, select **Update Existing Digital Humans** to apply the change to all Digital Humans of the agent. Otherwise only new Digital Humans get the change.

## Agent variables

Use an agent variable for a value that every Digital Human of one agent shares, for example a business name or a plan. Set them in **Agent Variables** on the agent's **Simulation Settings** tab. They work for every connection type.

Bluejay reads agent variables when each run starts, so a change applies to existing Digital Humans on their next run. When names match, a Digital Human's trait overrides the agent variable, and the **Send-call variables** on its Digital Human card override both. The Digital Human knows agent variables like traits and says them when the agent asks. Unlike a trait, an agent variable never goes out as a SIP header.

### Variables in the text

Write `{{name}}` in the success criteria, intent, description, or personality text, and Bluejay fills in the Digital Human's value for that name before the run, for both voice and text. The grader sees the same filled-in success criteria, so `The agent confirmed account {{account_number}}` is graded against the real number. For a nested value, join the keys with dots, for example `{{investor_information.first_name}}`. A name with no value stays as written.

## Connection

- **Phone number** must be a number your organization owns.
- **Extension** is the keys the Digital Human presses after the call connects to an inbound agent, for example `1,2`. A comma adds a short pause.
- **Always On** makes the Digital Human answer calls on its phone number. While it is on, simulation runs can't call that number. Turn Always On off to run the Digital Human in a simulation.

Buy numbers under **Settings → Phone Numbers** in the [workspace](/administration/workspaces) where your Digital Humans live. A number stays in the workspace you bought it in, and the app lists only the current workspace's numbers.

With the API, list numbers with [Get Phone Numbers](/api-reference/endpoint/phone-numbers). Your AI assistant can list, buy, and release numbers through the [workspace MCP tools](/mcp/workspace-tools#phone-numbers).

## Write a good Digital Human

- Test one goal in each Digital Human. Booking, rescheduling, and cancelling are three Digital Humans.
- Write **Description / Intent** as what the caller wants. If you write "correctly" or "successfully", that text describes the agent, so move it to **Success Criteria**.
- Put who the caller is in a [persona](/test/simulations/personas), so the same test runs with any caller.
- Put grading that applies to every call in a [custom metric](/test/metrics).

| Setting | Do | Do not |
|---|---|---|
| Description / Intent | "You want to move your dentist appointment to next week." | "Make sure the agent correctly reschedules. If it asks for your date of birth, say March 3, 1980." |
| Success Criteria | "The agent moved the appointment and confirmed the new date." | "The caller gives the date of birth and stays polite." |

### Make runs repeatable

An "if the agent says X, the caller does Y" rule in the intent is only a suggestion to the model, so the caller may not follow it on every run. Move it to the setting that fixes it:

| Need | Setting |
|---|---|
| A fixed value, for example a date of birth | [Traits](#traits) |
| A fixed value for every Digital Human of an agent | [Agent variables](#agent-variables) |
| A fixed line, keypad entry, or pause | [Scripted Responses](/test/simulations/personas#scripted-responses) |
| A fixed opening line | **Speaks First** |
| The same call on each run | **Creativity** from 0.0 to 0.3 |

Before you create a batch, run one Digital Human and read the transcript. Bluejay accepts a configuration that has no effect, for example a scripted response that never matches, so the transcript is where you see whether each setting worked.

To test a phone tree, draw an IVR Flow on the **Scenario Builder** page and run it with the [IVR Flow](/test/simulation-types/ivr-flow) simulation type.

## Communities

A Community is a saved group of Digital Humans that you can reuse in any simulation, which makes it a test suite for an agent or a flow.

Group the Digital Humans that cover one agent or one flow into a Community. Select the Community when you create a simulation, so each agent version runs against the same callers and the results compare directly.

When an agent fails on a real conversation, create a Digital Human that recreates the failure and add it to the Community. The next run then tests for that failure again.

## Backwards compatibility

- A Digital Human with no personas runs exactly as before. Existing Digital Humans from simulations without Personalities start with none.
- Every API call, CSV, MCP tool and [Bluejay as Code](/bluejay-as-code/overview#personas) file that worked before still works. `persona_ids` is optional everywhere.
- Personalities are now personas. A simulation that had Personalities selected now has those personas on each of its Digital Humans, so it runs once as each persona.
