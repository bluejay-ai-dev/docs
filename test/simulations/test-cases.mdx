A test case is one thing a caller tries to do, with the checks that decide whether your agent passed. Keep your test cases on the **Test Cases** tab and make Digital Humans from them with any of your [personas](/test/simulations/personas).

## Bring your test cases

If your test cases already live in a spreadsheet, upload them: see [Upload CSV](/test/simulation-types/upload-digital-humans). A [simulation plan](/test/simulations/create) also writes test cases for you and saves them here when you run. To add one by hand, open **Digital Humans**, go to the **Test Cases** tab, and click **New test case**.

## Make Digital Humans

Select test cases on the **Test Cases** tab, open **Actions**, choose **Create digital humans**, and pick the personas to pair them with. Bluejay makes one Digital Human for each test case and persona, so three test cases and two personas make six Digital Humans.

- Each Digital Human copies the test case and the persona when it is made, and is tagged `Test case: <name>` and `Persona: <name>`, so you can see where it came from and filter by it.
- After that it is an ordinary Digital Human. Edit it freely: the test case and persona stay as they were.
- An edit to a test case changes only Digital Humans you make afterwards.

## Fields

| Field | Write |
|---|---|
| Name | A short label for the test, for example "Late order tracking". |
| Intent | What the caller wants, in one or two sentences. |
| Success Criteria | Agent outcomes the transcript can show. See [Success criteria](#success-criteria). |
| Tool Adherence | The tool calls the agent must make. |
| Traits | Facts the caller gives when asked, such as a member ID. See [Traits](/test/simulations/digital-humans#traits). |
| Tags | Labels to filter and group by. |

## Success criteria

Bluejay grades each check on its own, and a conversation passes only when every check passes. Write one check almost always. Add a second only when the test must verify outcomes that pass or fail independently, such as booking the slot and also texting the confirmation.

## Write a good test case

- Test one goal in each test case. Booking, rescheduling, and cancelling are three test cases.
- Write the intent as what the caller wants. If you write "correctly" or "successfully", that text describes the agent, so move it to **Success Criteria**.
- Keep how the caller sounds and acts out of the test case. That belongs on the [persona](/test/simulations/personas), so the same test pairs with any caller.
