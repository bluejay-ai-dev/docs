## Call statuses

The API returns the status value in capitals, for example `NO_CONNECTION`.

### Final statuses

| Status | Value | Meaning |
|---|---|---|
| <span className="bj-status bj-status-completed"><Icon icon="circle-check" size={12} />Completed</span> | `COMPLETED` | The call ran and was scored. Pass or fail shows separately. |
| <span className="bj-status bj-status-no-connection"><Icon icon="plug-circle-xmark" size={12} />No Connection</span> | <Code>NO_CONNECTION</Code> | Bluejay could not reach your agent. |
| <span className="bj-status bj-status-no-answer"><Icon icon="phone-slash" size={12} />No Answer</span> | `NO_ANSWER` | Bluejay reached the line, but nobody engaged. |
| <span className="bj-status bj-status-call-dropped"><Icon icon="phone-arrow-down-left" size={12} />Call Dropped</span> | <Code>CALL_DROPPED</Code> | The call started, then the line dropped. Bluejay scores the transcript up to the drop. |
| <span className="bj-status bj-status-out-of-funds"><Icon icon="wallet" size={12} />Out of Funds</span> | <Code>OUT_OF_FUNDS</Code> | Your Bluejay balance ran out. |
| <span className="bj-status bj-status-system-error"><Icon icon="triangle-exclamation" size={12} />System Error</span> | <Code>SYSTEM_ERROR</Code> | A Bluejay service failed. |
| <span className="bj-status bj-status-custom-error"><Icon icon="circle-exclamation" size={12} />Custom Error</span> | <Code>CUSTOM_ERROR</Code> | The transcript matched the custom error prompt in the simulation settings. |
| <span className="bj-status bj-status-cancelled"><Icon icon="ban" size={12} />Cancelled</span> | `CANCELLED` | You stopped the call before it ran or before anything was recorded. |

### In-progress statuses

| Status | Value | Meaning |
|---|---|---|
| <span className="bj-status bj-status-initializing"><Icon icon="hourglass-start" size={12} />Initializing</span> | `INITIALIZING` | Bluejay is preparing the call. |
| <span className="bj-status bj-status-queued"><Icon icon="clock" size={12} />Queued</span> | `QUEUED` | The call waits to start. |
| <span className="bj-status bj-status-ready"><Icon icon="circle-dot" size={12} />Ready</span> | `READY` | Bluejay loaded the test data. The call is ready to start. |
| <span className="bj-status bj-status-dispatched"><Icon icon="paper-plane" size={12} />Dispatched</span> | `DISPATCHED` | Bluejay sent the call to a call worker. |
| <span className="bj-status bj-status-running"><Icon icon="phone-volume" size={12} />Running</span> | `RUNNING` | The conversation is in progress. |
| <span className="bj-status bj-status-evaluation-pending"><Icon icon="hourglass-half" size={12} />Evaluation Pending</span> | <Code>CONVERSATION_ENDED</Code> | The conversation ended and waits for scoring. |
| <span className="bj-status bj-status-evaluating"><Icon icon="spinner" size={12} />Evaluating</span> | `EVALUATING` | Bluejay is running the metrics. |

You can cancel a call while its status is one of these:

- `INITIALIZING`
- `QUEUED`
- `READY`
- `DISPATCHED`

You can end a `RUNNING` call. If nothing was recorded when it ends, its status is `CANCELLED`.

## Error codes

Each failed call has an `error_code` and a message that say what went wrong. The codes are grouped by the call's status. In a Customer Journeys run, a step that ends with an error status cancels the later steps with `STEP_SKIPPED`.

### No Connection

Usually a problem in your configuration or your provider plan. In a code, `<PROVIDER>` is the name of your voice platform. The Limits section of your platform page under **Integrations** lists its exact codes.

| Codes | Meaning | What to do |
|---|---|---|
| <Code>WEBSOCKET_AUTH_FAILED</Code> | Your WebSocket endpoint rejected the credentials that Bluejay has. | Update the username and password on the agent. |
| <Code>{"<PROVIDER>_AUTH_FAILED"}</Code> | Your provider rejected the API key that Bluejay has. | Update the key in the integration settings. |
| <Code>{"MISSING_<PROVIDER>_INTEGRATION"}</Code> | The provider integration is not connected or not complete. | Connect the integration. |
| <Code>{"<PROVIDER>_INTEGRATION_DECRYPT_FAILED"}</Code> | Bluejay could not decrypt the stored credentials. | Connect the integration again. |
| <Code>{"MISSING_<PROVIDER>_AGENT_ID"}</Code><br /><Code>{"MISSING_<PROVIDER>_ASSISTANT_ID"}</Code> | The agent or assistant ID is empty. | Set the ID on the agent. |
| <Code>OUTBOUND_TRIGGER_FAILED</Code> | Your [outbound trigger webhook](#outbound-trigger-webhook) did not return a `2xx` status after 3 tries. | Check the URL and that your endpoint answers within 15 seconds. |
| <Code>{"<PROVIDER>_BRIDGE_CONNECT_FAILED"}</Code><br /><Code>{"<PROVIDER>_SESSION_SETUP_FAILED"}</Code> | The provider accepted the connection but did not start a session. Often temporary. | Run the call again. |
| <Code>UNUSABLE_CALLER_ID</Code><br /><Code>INVALID_PHONE_NUMBER</Code><br /><Code>INVALID_SIP_DESTINATION</Code><br /><Code>SIP_DIAL_FAILED</Code> | The caller ID is not verified, the destination is not valid, or the SIP dial failed. | Check the number or SIP destination. |
| <Code>DYNAMIC_ENDPOINT_FAILED</Code> | Bluejay could not get a SIP endpoint from the dynamic SIP webhook of the agent. | Check that the webhook is reachable and returns an endpoint. |
| <Code>CUSTOMER_CONCURRENCY_LIMIT</Code> | Your provider's concurrent-call limit was reached. | Raise the limit or run fewer calls at once. |
| <Code>NO_CONNECTION_TYPE</Code> | The agent has no connection type. | Set a connection type. |

### No Answer

The problem is on your side: your agent or your line.

| Code | Meaning |
|---|---|
| `NO_ANSWER` | The phone rang and nobody answered. |
| <Code>CALL_REJECTED</Code> | Your agent rejected the call (SIP 486 or 603). |
| <Code>AGENT_HUNG_UP_BEFORE_SPEECH</Code> | Your agent answered, then hung up before it spoke. |
| <Code>AGENT_NO_RESPONSE</Code> | Your agent connected, but did not reply when the Digital Human spoke. |
| <Code>INBOUND_NO_INCOMING_CALL</Code> | Inbound Digital Humans only. Your agent did not call the Digital Human. |
| <Code>STEP_NO_ACTIVITY</Code> | A Customer Journeys step had no call or message before its deadline. |

Make sure your agent is online, accepts calls from the Bluejay caller ID, and routes Bluejay traffic correctly.

### Call Dropped

Usually a problem with your agent or your provider. Check your provider status page and your recent agent changes.

| Codes | Meaning |
|---|---|
| <Code>{"<PROVIDER>_AGENT_ERROR"}</Code> | Your provider agent reported an error during the call. |
| <Code>{"<PROVIDER>_AGENT_START_FAILED"}</Code> | Your provider agent did not start its turn. |
| <Code>{"<PROVIDER>_MONITORING_ERROR"}</Code> | Bluejay lost the monitoring connection to your provider. |
| <Code>{"<PROVIDER>_CONNECTION_FAILED"}</Code><br /><Code>BRIDGE_DISCONNECTED</Code> | The audio bridge between Bluejay and your provider stopped. |

### Out of Funds

`INSUFFICIENT_BALANCE`: your balance reached zero. Add funds in **Settings** > **Billing**, then run the calls again.

### System Error

The problem is in Bluejay, not in your agent. Run the call again. If the error repeats, ask in the [Slack community](https://join.slack.com/t/bluejaycommunity/shared_invite/zt-442xk85k5-Qkbq65wVOxK~1FHU5OadEA).

| Code | Meaning |
|---|---|
| <Code>HYDRATION_FAILED</Code> | Bluejay could not load the data to run the test. |
| <Code>EVAL_HYDRATION_FAILED</Code> | Bluejay could not load the data to score the call. |
| <Code>EVAL_NO_TRANSCRIPT</Code> | The transcript is missing or empty. |
| <Code>EVAL_AUDIO_CONVERSION_FAILED</Code> | Bluejay could not convert the call audio. |
| <Code>EVAL_PIPELINE_FAILED</Code> | The scoring step failed. |
| <Code>EVAL_QUEUE_FAILED</Code> | Bluejay could not queue the call for scoring. |
| <Code>RECORDING_URL_FAILED</Code> | Bluejay could not make a link to the recording. |
| <Code>END_SIGNAL_TIMEOUT</Code> | The call did not stop when asked, so Bluejay ended it. |
| <Code>AGENT_WORKER_LOST</Code> | The Bluejay worker for the call stopped responding. |
| <Code>SIP_TRUNK_RECYCLED</Code> | A newer simulation reused the phone number, so Bluejay stopped this test. |
| <Code>DB_WRITE_FAILED</Code> | A Bluejay database write failed. |
| `UNKNOWN` | Bluejay has no specific code for the failure. |
| <Code>UNKNOWN_LEGACY</Code> | The call ran before Bluejay recorded failure reasons. |

An email conversation can also show <Code>EMAIL_SENDER_MISMATCH</Code> without ending: your agent replied from an address that is not configured on it. The conversation stays open, and the code clears when a reply arrives from a configured address. Add the address to the agent's [reply-from addresses](/integrations/email#how-a-conversation-runs).

If the code is `EVAL_HYDRATION_FAILED`, `EVAL_PIPELINE_FAILED`, or `EVAL_QUEUE_FAILED`, you can retry only the scoring from the call panel.

## Outbound trigger webhook

For an outbound agent, your system starts each conversation. When a run starts, Bluejay sends a POST to your **Outbound Trigger Webhook URL**, and your system then calls or messages the Digital Human.

By default, the body has `phone_number` and `sim_conversation_id`. For a [SIP](/integrations/sip#outbound-agents) agent, it also has `sip_uri`, the SIP address your agent dials. To send other fields, set a body template with tokens such as `{{digital_human.phone_number}}`.

Return a `2xx` status from your webhook within 15 seconds. After 3 failed tries, the conversation ends with [`OUTBOUND_TRIGGER_FAILED`](#error-codes).

### Tokens and headers

Supported tokens include:

- `{{digital_human.id}}`
- `{{digital_human.name}}`
- `{{digital_human.phone_number}}`
- `{{digital_human.sip_uri}}`, for SIP agents only
- `{{digital_human.email}}`
- `{{digital_human.stable_email}}`
- `{{digital_human.intent}}`
- `{{sim_conversation_id}}`
- `{{simulation.id}}`
- `{{simulation.name}}`
- `{{agent.id}}`
- `{{agent.name}}`

Each request also has these headers:

- `X-Bluejay-Idempotency-Key` holds the conversation ID. Use it to ignore a repeated request.
- `X-Bluejay-Signature` holds the HMAC-SHA256 of the body, if the agent has a webhook signing key. [Verify it](/integrations/http-webhooks#verify-the-signature) before you place the call.

## Agent versions

An agent version is a numbered copy of the agent prompt. Save a new version before you change the prompt, so you can compare runs and go back.

Each new version gets the `latest` label. The first version also gets the `production` label, and it keeps it until you promote another version. A new simulation run and a production evaluation use the `production` version unless you select another one.

## Workflow

A workflow is the multi-agent graph of a provider agent, for example a root agent that hands off to sub-agents. It comes from your provider. Use the **Workflow** tab of Agent Settings to see and edit that graph, and to test each path through it with the [Workflow](/test/simulation-types/generate-from-workflow) simulation type.

**Pull** copies the graph from your provider into Bluejay. **Push** sends your Bluejay edits to the provider.

<Warning>
  Push changes the agent in your provider account. If that version is live, real callers get the change. Pull replaces Bluejay edits that you did not push.
</Warning>

To import a graph from a document, attach the document in a **Bluejay AI** chat and ask for a workflow. After you approve the draft, Bluejay AI saves it to the agent. You can import only to an agent that has no workflow provider. An imported workflow has no provider to sync with, so it has no Pull or Push: to change it, edit it in Bluejay or import an updated document.

## Knowledge Bases

A Knowledge Base holds the facts your agent must know. Bluejay uses it to check that your agent states those facts correctly, and it can also generate Digital Humans that ask about them.

### Add documents

Connect a Knowledge Base to the agents that use it, and add the same files, text, and web pages your agent uses.

A new document shows **Processing** while Bluejay reads it, and Bluejay uses it only after its status is **Ready**. If the status is **Failed**, add the document again.

![A Knowledge Base with URL, text, and PDF documents, all Ready](/images/knowledge-base-documents.png)

### Supported file types

<div className="table-fit">

| Source | Supported types | Maximum size |
|---|---|---|
| File | PDF (`.pdf`)<br />Text (`.txt`)<br />Markdown (`.md`, `.markdown`) | 100 MB for each file |
| File | HTML (`.html`, `.htm`) | 10 MB for each file |
| Text | Typed or pasted text | 1 MB. For more, upload a file. |
| URL | One web page | None |

### How Bluejay uses a Knowledge Base

| Feature | Use |
|---|---|
| Success evaluation | When a success criterion depends on facts, the judge searches the Knowledge Bases of the agent. |
| Hallucination check | If your organization turns on **Enable Hallucination Evaluations**, Bluejay checks the agent's answers against its Knowledge Bases. |
| Custom metrics | If a metric has <Code>settings.use_knowledge_base</Code> set to `true`, the judge can search the Knowledge Base. |
| Simulations | The [Knowledge Base](/test/simulation-types/natural-language#knowledge-base) simulation type makes Digital Humans across the topics in a Knowledge Base. |
