Use mock tool calls to test how your agent handles a tool result you choose, such as "two slots open on Thursday" or "order not found". During a simulation, the tool returns the Digital Human's canned result and your real system is never called, so runs are repeatable and touch no production data.

## How it works

1. Turn on **Mock tool results** in the agent's **Simulation Settings**. It applies to every Digital Human on that agent.
2. On each Digital Human, set the **Expected Output / Mock Result** of a tool under **Tool Adherence**. That output is the canned result.
3. Run the simulation. When the agent calls the tool, it gets the canned result.

How the canned result reaches your agent depends on the platform. See [Setup by provider](/test/simulations/mock-tools-setup).

## Set the canned result

In the app, edit a Digital Human. Under **Tool Adherence**, add the tool, then fill in:

- **Expected Parameters**: the arguments this mock is for. Leave it empty to match any call.
- **Expected Output / Mock Result**: the result your agent gets back. JSON or plain text.

With the API or MCP, set `expected_tool_calls` when you [create](/api-reference/endpoint/create-digital-human) or [update](/api-reference/endpoint/update-digital-human) a Digital Human. Each entry has `name`, `parameters` and `output`.

```json
{
  "expected_tool_calls": [
    {
      "name": "check_availability",
      "parameters": {"day": "Thursday"},
      "output": {"slots": ["Thursday 7:40 AM", "Thursday 4:05 PM"]}
    }
  ]
}
```

An entry without `output` is graded for tool adherence but never mocked.

## Which mock wins

A Digital Human can have several entries for one tool.

- Bluejay picks the first entry whose parameters all match the call's arguments. Values match as text, ignoring case and surrounding spaces. Arguments that the entry does not list are ignored.
- If no entry matches, Bluejay uses the first entry for that tool. Put a catch-all entry first.
- If the Digital Human has no entry for the tool, what happens depends on the platform. See [Setup by provider](/test/simulations/mock-tools-setup).

## Example

Your scheduling agent has a `check_availability` tool. You want to test that it reads back the times your calendar returns.

1. Turn on **Mock tool results** in the agent's **Simulation Settings**.
2. Create a Digital Human who asks for a Thursday appointment.
3. Under **Tool Adherence**, add `check_availability` with Expected Output `{"slots": ["Thursday 7:40 AM", "Thursday 4:05 PM"]}`.
4. Add the success criterion "The agent reads back the Thursday times that check_availability returned."

When the agent checks availability, it gets Thursday at 7:40 AM and 4:05 PM, and says those times to the caller. Every run sees the same result, and no real calendar is read.
