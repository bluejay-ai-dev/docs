Use mock tool calls to test how your agent handles a tool result you choose, such as "two slots open on Thursday" or "order not found". During a simulation, the tool returns the Digital Human's canned result and your real system is never called, so runs are repeatable and touch no production data.

## How it works

1. Turn on **Mock tool results** in the agent's **Simulation Settings**. It applies to every Digital Human on that agent.
2. On each Digital Human, fill in **Tool responses** with the result each tool should return.
3. Run the simulation. When the agent calls the tool, it gets that result.

How the result reaches your agent depends on the platform. See [Setup by provider](/test/simulations/mock-tools-setup).

## Set tool responses

In the app, edit a Digital Human. **Tool responses** lists the agent's tools, each with a box for its response, JSON or plain text. Leave a box empty and that tool runs for real. If the agent's tools aren't synced, type a tool name and click **Add Tool**.

Tool responses are separate from **Tool Adherence**. Tool Adherence grades which tools the agent calls; Tool responses only decide what the tools return. You can mock a tool without requiring it to be called.

With the API or MCP, set `tool_responses` when you [create](/api-reference/endpoint/create-digital-human) or [update](/api-reference/endpoint/update-digital-human) a Digital Human. It maps each tool name to its response.

```json
{
  "tool_responses": {
    "check_availability": {"slots": ["Thursday 7:40 AM", "Thursday 4:05 PM"]}
  }
}
```

A tool without an entry is not mocked. What happens then depends on the platform. See [Setup by provider](/test/simulations/mock-tools-setup).

## Example

Your scheduling agent has a `check_availability` tool. You want to test that it reads back the times your calendar returns.

1. Turn on **Mock tool results** in the agent's **Simulation Settings**.
2. Create a Digital Human who asks for a Thursday appointment.
3. Under **Tool responses**, set `check_availability` to `{"slots": ["Thursday 7:40 AM", "Thursday 4:05 PM"]}`.
4. Add the success criterion "The agent reads back the Thursday times that check_availability returned."

When the agent checks availability, it gets Thursday at 7:40 AM and 4:05 PM, and says those times to the caller. Every run sees the same result, and no real calendar is read.
