Bluejay supports multiple ways to test an agent depending on the channel, customer behavior, and system architecture you need to evaluate.

## What You'll Learn

- The different simulation categories available in Bluejay
- When to use each type based on your testing goals
- Which integrations map to which simulation types

## Voice Simulations

Voice simulations test phone-based customer journeys end to end. Bluejay places or receives calls through your telephony provider, runs the conversation with a Digital Human, captures the audio transcript, and evaluates it against your Custom Metrics.

| Integration | Description |
|-------------|-------------|
| [Telephony](/simulation-integrations/telephony) | Direct phone calls via your provider |
| [SIP](/simulation-integrations/sip) | SIP trunk-based voice connections |
| [LiveKit](/simulation-integrations/livekit) | LiveKit room-based voice sessions |

## Text Simulations

Text simulations test messaging and webhook-based interactions. Bluejay exchanges messages with your agent over HTTP, WebSocket, or SMS and evaluates the full conversation transcript.

| Integration | Description |
|-------------|-------------|
| [HTTP Webhooks](/simulation-integrations/http-webhooks) | Bidirectional HTTP messaging |
| [WebSockets](/simulation-integrations/websockets) | Real-time bidirectional messaging |
| SMS | SMS-based text agent flows |

## Simulation Types in the Create Dialog

When you click **Create Simulation**, you pick how the digital humans get built. The options:

| Type | What it does |
|------|-------------|
| **Goal Adherence** | Tests whether your agent achieves its specified goals during conversations |
| **Scenario Builder** | Generates fine-grained digital humans from scenarios you author, including turn-by-turn conversations |
| **IVR Flow** | Author an IVR phone tree and test how your agent navigates it; Bluejay plays the menus and your agent is the caller |
| **Generate From Workflow** | One persona per distinct path through your agent's synced multi-agent workflow |
| **Generate from Natural Language** | Describe test scenarios in plain language and let AI generate the digital humans |
| **Replay From Transcript** | Replay real conversation transcripts to verify your agent handles similar scenarios consistently |
| **Load Testing** | Tests performance, latency, and throughput under load |
| **Use Previous Digital Humans** | Select from your existing digital humans or communities |
| **Upload Custom Digital Humans** | Upload a CSV of custom digital human configurations |
| **Voicemail** | Simulates a voicemail machine: plays a greeting, then records the caller's message |
| **Customer Journeys** | A sequence of calls under one digital human (book, confirm, then cancel) with traits locked across the journey |

Red-teaming simulations (adversarial probing) are created from their own dedicated flow.

## Choosing the Right Type

| Goal | Recommended approach |
|------|-----------------|
| Validate a new agent build before launch | Goal Adherence |
| Catch regressions after a prompt change | Re-run the same simulation and compare runs |
| Test every conversation path | Generate From Workflow |
| Stress-test capacity | Load Testing |
| Benchmark across customer demographics | Run a Community |
