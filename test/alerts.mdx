Use an alert to have Bluejay tell your team when a metric in your simulation results crosses a threshold you set.

If you are setting up alerts for production calls, see [Alerts](/monitor/alerts).

To create alerts from code, use the [Alerts API](/api-reference/endpoint/create-alert).

## How alerts evaluate

A metric alert checks one of these:

- **Across a simulation run** checks each run when it completes.
- **Across the last N conversations** uses the agent's most recent N conversations, across runs.

For a pass/fail metric, the value is the percentage of conversations that passed (0 to 100).

A **System Failures** alert fires at once when one conversation in a run ends with the selected failure status.

An alert belongs to the workspace you create it in, and it can watch only that workspace's agents and simulations.

## Choose where each alert goes

Each alert has its own channels, so you can match the channel to how urgent the problem is. A channel stays off until you connect it.

## Incidents

PagerDuty and Better Stack receive incidents, and your escalation policy in that tool decides who gets the page. An alert opens one incident per run. Bluejay never resolves these incidents, so resolve them in PagerDuty or Better Stack.
