Use this type before a launch or a busy period, to see how your agent and your telephony hold up when many customers contact it at once.

## Set it up

<Steps>
  <Step title="Select the card">
    [Create a simulation](/test/simulations/create#create-a-simulation) and select the **Load Testing** card.

    <img className="block dark:hidden" src="/images/create-simulation-card-load-testing.png" alt="Load Testing card in the Create Simulation type picker" />
    <img className="hidden dark:block" src="/images/create-simulation-card-load-testing-dark.png" alt="Load Testing card in the Create Simulation type picker" />
  </Step>
  <Step title="Set the number of calls">
    Set **Number of calls**. Each call is one Digital Human.

    <img className="block dark:hidden" src="/images/load-testing.png" alt="The Load Testing General tab with Number of calls set to 25" />
    <img className="hidden dark:block" src="/images/load-testing-dark.png" alt="The Load Testing General tab with Number of calls set to 25" />
  </Step>
  <Step title="Set the load">
    On the **Simulation Settings** tab, set **Max concurrent conversations** to the load you want to test. This is how many calls run at the same time.
  </Step>
  <Step title="Generate">
    Click **Save**, then **Generate Digital Humans**.
  </Step>
</Steps>

## Limits

- One load test makes a maximum of 100 Digital Humans. To test more, [contact the Bluejay team](https://cal.com/rohanv/15min).
- For an outbound agent, you cannot set **Max concurrent conversations** in the app, and Bluejay dials every Digital Human at once. To limit it, set `max_concurrent` with the [Simulation API](/api-reference/endpoint/create-simulation).
- Your provider can have its own concurrent-call limit. If a call goes over it, the call ends with [`CUSTOMER_CONCURRENCY_LIMIT`](/test/simulations/reference#error-codes).
