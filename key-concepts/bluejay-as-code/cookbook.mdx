This page gives payload examples for each entity type in [Bluejay as Code](/key-concepts/bluejay-as-code/overview). For the full field lists, see [create-digital-human](/api-reference/endpoint/create-digital-human), [add-agent](/api-reference/endpoint/add-agent), [update-simulation](/api-reference/endpoint/update-simulation), and [create-custom-metric](/api-reference/endpoint/create-custom-metric).

## Renamed fields

| Payload field | API field | Entity |
|---|---|---|
| `description` | `intent` | Digital Human |
| `human_name` | `name` | Digital Human |
| `temperature` | `creativity` | Digital Human |
| `description` | `prompt` | Custom metric (old files only) |

On push, a Digital Human also accepts `"accent": "en_american_masculine"` in the form `language_accent_gender`. Bluejay splits it into `language`, `accent`, and `gender`. Pull always returns the three fields.

## Digital Human types

The `tag` field sets the type. A customer journey uses `journey_steps` in place of a tag. The examples omit `simulations`.

<AccordionGroup>
  <Accordion title="Base">
    ```json
    {
      "bluejay_as_code_id": "a0e7b3d2-4c8f-4a91-b3e6-1d5f9c2e7a44",
      "human_name": "Maria Alvarez",
      "description": "New patient booking her first physical with Dr. Patel.",
      "success_criteria": "Agent books a Tuesday or Thursday morning slot with Dr. Patel."
    }
    ```
  </Accordion>

  <Accordion title="Voicemail">
    Set `tag` to `voicemail-custom` for your own greeting, or `voicemail-ai-generated` for a generated greeting. For `voicemail-ai-generated`, set `speaks_first_config.mode` to `"ai_generated"` and omit `message`. A voicemail Digital Human needs no `description` or `success_criteria`.

    ```json
    {
      "bluejay_as_code_id": "9b3c7d5e-2a41-4a0f-8c6b-3e2d1f9a7c50",
      "human_name": "Voicemail Line",
      "tag": "voicemail-custom",
      "speaks_first_config": {
        "speaks_first": true,
        "mode": "custom",
        "message": "Hi, you have reached Maria. Leave a message after the tone."
      }
    }
    ```

    <Note>
      If `tag` has more than one label, put the voicemail label first. Bluejay checks only the first label.
    </Note>
  </Accordion>

  <Accordion title="Transcript replay">
    `formatted_transcript` replays a real call in place of `description` and `success_criteria`. `original_transcript` takes raw text, and Bluejay uses one LLM call to extract the turns.

    ```json
    {
      "bluejay_as_code_id": "6f1a9c3e-7b2d-4e11-9a5f-3c8d2b1e6a90",
      "human_name": "Replayed Caller",
      "formatted_transcript": [
        { "role": "caller", "utterance": "Hi, I need to reschedule my appointment." },
        { "role": "agent", "utterance": "Sure, what day works better for you?" }
      ]
    }
    ```
  </Accordion>

  <Accordion title="Customer journey">
    A [customer journey](/test/simulations/customer-journeys) runs one call per step, in order. Bluejay adds the `Customer Journey` tag. `step` values must start at 1 and have no gaps. Each step needs an `intent`.

    ```json
    {
      "bluejay_as_code_id": "d4f8a2c1-6b3e-4a09-8f27-1c5e9b0d3a76",
      "human_name": "Returning Caller",
      "journey_steps": [
        { "step": 1, "intent": "Book a Tuesday morning physical with Dr. Patel", "success_criteria": "Appointment booked and confirmation number read back" },
        { "step": 2, "intent": "Call back to cancel the appointment", "success_criteria": "Appointment cancelled" }
      ]
    }
    ```
  </Accordion>

  <Accordion title="Scenario Builder">
    [Scenario Builder](/key-concepts/scenario-builder/overview) generates Digital Humans with the `Scenario` tag, `workflow_v2_id`, `workflow_path_index`, and `enriched_playback`. Do not write `enriched_playback` by hand, because it does not stay in sync with the scenario graph.
  </Accordion>

  <Accordion title="Red teaming">
    [Red teaming](/key-concepts/red-teaming/overview) generates Digital Humans with `attack_vector`, `attack_type`, and `attack_plan`. Start these from [red teaming](/key-concepts/red-teaming/launching-a-test), not from Bluejay as Code.
  </Accordion>
</AccordionGroup>

`livekit_metadata` comes from the agent LiveKit connection settings. Do not write it by hand.

  "name": "Scheduling Coverage",
  "max_concurrent": 5,

## Custom metrics

```json
{
  "bluejay_as_code_id": "2b8d4c1f-9a3e-4f72-b5c0-6e1d8a7f3c44",
  "name": "DOB Verified Before PHI",
  "prompt": "The agent verifies the caller's date of birth before it discusses patient information.",
  "metric_type": "llm_judge",
  "eval_segment": "agent",
  "scope": "all",
  "response_type": "pass_fail"
}
```

`metric_type` sets which fields apply. The `tool_call` and `audio_*` types read `settings` in place of `prompt`.

### Conditional metrics

A conditional metric runs only on conversations that match its `settings.fire_conditions`. On other conversations the result is not applicable.

```json
{
  "bluejay_as_code_id": "e6b0d419-2c7a-4f35-8d91-5a3f7c2e0b18",
  "name": "Copay Explained",
  "prompt": "Did the agent state the copay amount for the visit?",
  "metric_type": "llm_judge",
  "response_type": "pass_fail",
  "settings": {
    "fire_conditions": {
      "groups": [
        { "conditions": [{ "type": "workflow_node", "node_id": "node_4a71c9e2b83d5f60" }] }
      ]
    }
  }
}
```

The conditions in a group use the group `join`. The groups use the outer `join`. Both default to `and`. You can use 10 conditions maximum across all groups.

| `type` | Fires when | Fields |
|---|---|---|
| `workflow_node` | The call reached a node in the agent workflow | `node_id` |
| `tool_call` | The agent called a tool | `tool_name` |
| `metric` | Another metric on the call has a given score | `metric_id`, `operator`, `value` |

Operators: `equals`, `not_equals`, `greater_than`, `less_than`, `greater_than_or_equal`, `less_than_or_equal`, `contains`, `not_contains`.

Get node IDs from `GET /v1/agents/{agent_id}/workflow/summary`. Old files can have `settings.fire_node_ids`, a flat list of node IDs. It still works.

### Composite metrics

A composite metric reads the scores of other metrics on the same call. It makes no LLM call.

- List the input metrics in `settings.composite.variables`. A metric that is not a number needs a `value_map`.
- In a formula, name a metric by its ID in double quotes.
- Formula operators: `+`, `-`, `*`, `/`, `%`, `**`. Functions: `min`, `max`, `abs`, `round`, `floor`, `ceil`.

For a number, set `output_type` to `quantitative` and write a `master_formula`:

```json
{
  "bluejay_as_code_id": "3d1f8b60-9a4c-4e27-b5d3-0c6e2a7f4193",
  "name": "Scheduling Quality Score",
  "prompt": "Weighted 1-5 score from scheduling clarity and confirmed details.",
  "metric_type": "composite",
  "response_type": "quantitative",
  "min_value": 1,
  "max_value": 5,
  "settings": {
    "composite": {
      "output_type": "quantitative",
      "variables": [
        { "metric_id": "7c4e2a10-3f8b-4d95-8e62-1a9d5c0b4f37" },
        { "metric_id": "9f3a1c7e-5b2d-4e88-a4f1-0c7b3d6a9e21", "value_map": { "pass": 5, "fail": 1 } }
      ],
      "master_formula": "round(\"7c4e2a10-3f8b-4d95-8e62-1a9d5c0b4f37\" * 0.6 + \"9f3a1c7e-5b2d-4e88-a4f1-0c7b3d6a9e21\" * 0.4)"
    }
  }
}
```

For a label, set `output_type` to `categorical`, set `response_type` to `enum`, and write `rules`. Bluejay checks the rules in order and uses the first match. If no rule matches, the result is not applicable. You can use 10 rules maximum, with 10 conditions maximum each.

```json
"rules": [
  {
    "output": "Clean",
    "conditions": { "groups": [{ "join": "and", "conditions": [
      { "metric_id": "7c4e2a10-3f8b-4d95-8e62-1a9d5c0b4f37", "operator": "greater_than_or_equal", "value": 4 },
      { "metric_id": "9f3a1c7e-5b2d-4e88-a4f1-0c7b3d6a9e21", "operator": "equals", "value": 1 }
    ]}]}
  },
  {
    "output": "Poor",
    "conditions": { "groups": [{ "conditions": [
      { "metric_id": "7c4e2a10-3f8b-4d95-8e62-1a9d5c0b4f37", "operator": "less_than", "value": 4 }
    ]}]}
  }
]
```

A rule can read only a metric that `variables` lists. Each result stores its calculation in `reasoning`.

<Warning>
Risk: a rejected push. A fire condition or composite variable that points at a conditional metric returns `422`. A metric that other metrics read cannot become conditional or composite.
</Warning>
