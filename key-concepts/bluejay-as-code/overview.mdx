## Pull the payload

```bash
curl https://api.getbluejay.ai/v1/bluejay-as-code/simulation/$SIM_ID \
  -H "X-API-Key: $BLUEJAY_API_KEY" \
  -o simulation.json
```

The root type is `simulation`, `agent`, `digital-human`, or `custom-metric`. The root ID is the entity ID or its `bluejay_as_code_id`. The payload includes the related entities.

```json simulation.json
{
  "agents": [
    {
      "bluejay_as_code_id": "f3d2a87c-1e4b-4b9a-9c2d-7f1e6b5a4c33",
      "name": "Front Desk Scheduler",
      "system_prompt": "You are the front desk scheduling agent for Cedar Park Family Medicine. Verify the caller's date of birth before you discuss patient information."
    }
  ],
  "simulations": [
    {
      "bluejay_as_code_id": "b1a04e88-7c2f-4d23-9a5e-2f8c6d1b7a09",
      "name": "Scheduling Coverage"
    }
  ],
  "digital_humans": [
    {
      "bluejay_as_code_id": "a0e7b3d2-4c8f-4a91-b3e6-1d5f9c2e7a44",
      "human_name": "Maria Alvarez",
      "description": "New patient booking her first physical with Dr. Patel.",
      "success_criteria": "Agent books a Tuesday or Thursday morning slot with Dr. Patel.",
      "simulations": ["b1a04e88-7c2f-4d23-9a5e-2f8c6d1b7a09"]

  ],
  "custom_metrics": [
    {
      "bluejay_as_code_id": "2b8d4c1f-9a3e-4f72-b5c0-6e1d8a7f3c44",
      "name": "DOB Verified Before PHI",
      "prompt": "The agent verifies the caller's date of birth before it discusses patient information."
    }
  ]
}
```

## Edit the payload

- To update an entity, change its fields.
- To add an entity, append an object with a new `bluejay_as_code_id`. Generate the UUID one time (for example with `uuidgen`) and commit it.
- To unlink a Digital Human or custom metric, remove it from the list that links it.

Each entity takes the same fields as its API resource. A few Digital Human fields have different names. See the [Cookbook](/key-concepts/bluejay-as-code/cookbook).

A simulation has no field for its agent. If the payload has one agent, Bluejay links the new simulation to it. If the payload has more agents, list the simulation `bluejay_as_code_id` in the `simulations` array of its agent.

## Push the payload

```bash
curl https://api.getbluejay.ai/v1/bluejay-as-code \
  -H "X-API-Key: $BLUEJAY_API_KEY" \
  -H "Content-Type: application/json" \
  --data @simulation.json
```

```json response
{
  "valid": true,
  "errors": [],
  "actions": [
    "Updated agent 'Front Desk Scheduler'",
    "Created digital human 'Eleanor Pham'",
    "Linked 1 existing digital human(s) to simulation"
  ],
  "simulation_id": 1284
}
```

Bluejay matches each entity by `bluejay_as_code_id`:

| Case | Result |
|---|---|
| New `bluejay_as_code_id` | Bluejay creates the entity. |
| Known `bluejay_as_code_id` | Bluejay updates the entity. |
| Digital Human missing from a simulation's links | Bluejay removes it from the simulation. The Digital Human stays. |
| Custom metric missing from an agent's links | Bluejay detaches it from the agent. The metric stays. |

Each link list in the payload replaces the current links on push.

<Warning>
Risk: a silent failure. A payload with errors returns HTTP `200` with `"valid": false` and an `errors` list. Check `valid` after every push.
</Warning>

A push returns HTTP `400` if a link points to a Digital Human or custom metric that is in neither the payload nor Bluejay, or if a new simulation does not have exactly one agent.

## Claude Code skill

The skill file gives Claude Code the payload shape and the rules for pull and push.

<Card title="Download skill" icon="download" href="https://raw.githubusercontent.com/bluejay-ai-dev/docs/main/key-concepts/bluejay-as-code/skill.txt">
  `skill.txt`

1. Download the file.
2. Save it in your repository, for example as `bluejay-as-code.skill.txt`.
3. In Claude Code, mention the file with `@bluejay-as-code.skill.txt` in your request.
