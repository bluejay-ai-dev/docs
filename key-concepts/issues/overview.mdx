An Issue is a failure that Bluejay finds in evaluated conversations and groups with the conversations it affects. Bluejay writes the title, description, and conversation list. You cannot edit them.

<Tabs>
  <Tab title="Simulations">
    Open Simulations → Issues. Issues come from evaluated simulation results. The API is under `/v1/simulations/issues`.
  </Tab>
  <Tab title="Production">
    Open Observability → Issues. Issues come from evaluated production Conversations. The API is under `/v1/observability/issues`.
  </Tab>
</Tabs>

## Issue types

| UI label | API `type` | Meaning |
|----------|------------|---------|
| Agent Failure | `non_deterministic` | Bluejay grouped similar failures into one Issue. |
| System Error | `deterministic` | Bluejay matched a known error. |

## Triage an Issue

The list groups Issues under Open, In Progress, Resolved, and Ignored. Each header shows the count for the current filters.

You can change these fields from the list or the Issue page:

| Field | Values |
|-------|--------|
| Status | Open, In Progress, Resolved, Ignored. |
| Priority | Urgent, High, Medium, Low. Empty until someone sets it. |
| Assignee | A member of your organization. |
| Due date | A date, or empty. |

Filter the list by search text, agent, type, status, source, assignee, priority, or percent of conversations.

## API

[List Issues](/api-reference/endpoint/list-issues) returns Issues by most recent `last_seen_at` first, 50 per page by default, 200 maximum. Filter by `status`, `priority`, `type`, or `assignee_id`. [Get Issue](/api-reference/endpoint/get-issue) returns one Issue. [Update Issue](/api-reference/endpoint/update-issue) sets `status`, `priority`, `assignee_id`, or `due_date`.
