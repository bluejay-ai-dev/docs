To get notified when a metric crosses a threshold in simulations or in production, create an alert. Bluejay sends the alert to the channels that you connect in [Alert Notifications](/integrations/notifications). To start an automated flow when an alert fires, subscribe a URL to the alert events in [Webhooks](/key-concepts/webhooks/overview#events).

To catch a slow drop in quality, watch a pass rate over many conversations. To catch a failure that must never happen, watch a single event.

## How alerts evaluate

<Tabs>
  <Tab title="Simulations">
    A simulation alert checks one of these:

    - **Across a simulation run** checks each run when it completes.
    - **Across the last N conversations** uses the agent's most recent N conversations, across runs.

    For a pass/fail metric, the value is the percentage of conversations that passed (0 to 100).

    A **System Failures** alert fires at once when one conversation in a run ends with the selected failure status.
  </Tab>
  <Tab title="Production">
    A production alert counts the conversations that match the condition in a window, either a time interval or the last N conversations. The alert enters alarm when at least N conversations match, and recovers when the count drops below 80% of N (minimum 1).

    With the last N conversations as the window, the alert does not fire until N conversations exist.

    For a metric where one failure is too many, for example hallucination, set N to 1.
  </Tab>
</Tabs>

## Alert fields

To create an alert with the [Alerts API](/api-reference/endpoint/create-alert) or the MCP tools, set these fields:

| Field | Description |
|-------|-------------|
| `source_scope` | `observability`, `simulation`, or `all`. |
| `entity_type` | `custom_metric`, `standard_metric`, `custom_goal`, `metadata_field`, or `system_failure`. |
| `entity_field` | The metric or field to watch. |
| `operator` | `equals`, `not_equals`, `greater_than`, `less_than`, `greater_than_or_equal`, `less_than_or_equal`, `contains`, `not_contains`. |
| `comparison_value` | The value to compare against, as a string. |
| `min_events` | Production only. The number of matching events. Default 10. |
| `min_events_type` | `events` (default) makes `min_events` a count. `percentage` makes it a percentage of events, 0 to 100. |
| `threshold_time_interval` | Production: the window in seconds (default 600). Simulations: the number of recent completed runs (default 1). |
| `sample_size` | The last N conversations in place of a time window. Minimum 30. |
| `aggregation` | Simulations only. `avg`, `min`, `max`, `count`, or `none`. |
| `simulation_id` | Simulations only. Limits the alert to one simulation. |
| `agent_ids`, `applies_to_all_agents` | The agents the alert watches. |
| `notification_channels` | A list of `{ type, target }`. See [Alert Notifications](/integrations/notifications). |
