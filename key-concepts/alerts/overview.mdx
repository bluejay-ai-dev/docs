An alert notifies your team when a metric crosses a threshold in simulations or in production.

## Create an alert

<Tabs>
  <Tab title="Simulations">
    1. Open Simulations → Alerts and create an alert.
    2. Select **All simulations** or **Specific simulation**.
    3. Select a metric.
    4. Set the condition.
    5. Select the agents.
    6. Select the notification channels.

    The condition reads: **Alert me when** the [average | lowest result | highest result] of the metric **across a simulation run** or **across the last N conversations** is [operator] [value].

    - **Across a simulation run** checks each run when it completes.
    - **Across the last N conversations** uses the agent's most recent N conversations, across runs.
    - For a pass/fail metric, the value is the percentage of conversations that passed (0 to 100).
    - A **System Failures** alert fires at once when one conversation in a run ends with the selected failure status.
  </Tab>
  <Tab title="Production">
    1. Open Observability → Alerts and create an alert.
    2. Under **Trigger**, select a metric or a metadata field.
    3. Set the operator and the value.
    4. Set **for at least** N events in a window.
    5. Under **Scope**, select the agents.
    6. Select the notification channels.

    The alert enters alarm when at least N conversations match the condition in the window. It recovers when the count drops below 80% of N (minimum 1).

    - The window is a time interval or the last N conversations.
    - With the last N conversations, the alert does not fire until N conversations exist.

    For a metric where one failure is too many, for example hallucination, set N to 1.
  </Tab>
</Tabs>

## Notification channels

| Channel | Target |
|---------|--------|
| Email | All team members, or specific email addresses. |
| Slack | A channel. Connect Slack first in [Notifications](/integrations/notifications). |
| PagerDuty | A routing key. |
| Better Stack | Uses your organization's Better Stack token. |

To start an automated flow when an alert fires, subscribe a URL to **Observability alert triggered** or **Simulation alert triggered** in Settings → [Webhooks](/key-concepts/webhooks/overview).

## Alert fields

| Field | Description |
|-------|-------------|
| `source_scope` | `observability`, `simulation`, or `all`. |
| `entity_type` | `custom_metric`, `standard_metric`, `custom_goal`, `metadata_field`, or `system_failure`. |
| `entity_field` | The metric or field to watch. |
| `operator` | `equals`, `not_equals`, `greater_than`, `less_than`, `greater_than_or_equal`, `less_than_or_equal`, `contains`, `not_contains`. |
| `comparison_value` | The value to compare against, as a string. |
| `min_events` | Production only. The number of matching events. Default 10. |
| `threshold_time_interval` | Production: the window in seconds (default 600). Simulations: the number of recent completed runs (default 1). |
| `sample_size` | The last N conversations in place of a time window. Minimum 30. |
| `aggregation` | Simulations only. `avg`, `min`, `max`, `count`, or `none`. |
| `simulation_id` | Simulations only. Limits the alert to one simulation. |
| `agent_ids`, `applies_to_all_agents` | The agents the alert watches. |
| `notification_channels` | A list of `{ type, target }`. `type` is `email`, `slack`, `pagerduty`, or `betterstack`. |
