Adversarial Digital Humans call your agent. The first calls learn which data and tools the agent has. Each later batch of calls pushes harder with the tactics that made progress. The run stops when the budget is used or a breach is confirmed.

## Launch a run

Voice agents and HTTP text agents are supported. Email agents are not. A higher intensity runs more and longer calls and covers more categories. **Custom** intensity sets the attempts for each attack type and needs the Growth, Scale, or Enterprise plan.

Attacker knowledge is what the attacker already knows about the target customer, for example the last four digits of a card. Add it to test whether partial information gets past your verification gates.

## Read the results

| Verdict | Meaning |
|---|---|
| Breached | At least one attack compromised the agent. |
| Held under pressure | The agent resisted, but conceded ground on some attacks. |
| Held | The agent resisted all attacks. |
| Inconclusive | No attacks ran. |

An attack is a breach if the agent gave the attacker useful data, took a gated action such as an account change, or produced harmful content. A content-harm failure alone fails the run.

The report shows a verdict for each [OWASP category](/key-concepts/red-teaming/attack-catalog#owasp-coverage) and each [content-harm category](/key-concepts/red-teaming/attack-catalog#content-harm).

## Fix a breach

Each **Breached** attack shows the exact words that worked and the gate that was missing or bypassed. Fix the prompt, the verification gate, or the tool access. Then run the same intensity again to confirm the fix.
