The **Scenario Builder** page has two item types:

| Type | What it models |
|---|---|
| Scenario | A conversation your agent must handle. Agent turns define what your agent must say. User turns define what the Digital Human says. |
| IVR Flow | A phone tree with menus, hold steps, and transfer points. Your agent calls in, and the Digital Human plays the IVR system. |

<Note>
Scenarios are for voice agents only.
</Note>

## Build and run a scenario

You can also paste a JSON [definition](#example-definition). Each path from the start node to a leaf becomes one Digital Human, so every branch you add adds a test. To run a scenario, use the **Scenario Adherence** simulation type. To run an IVR Flow, use the **IVR Flow** type.

With the API, call [Generate Digital Humans](/api-reference/endpoint/generate-digital-humans) with `workflow_adherence_v2`, a map of scenario ID to the number of Digital Humans. Bluejay caps each count at 200.

```json
{
  "agent_id": 123,
  "simulation_id": 456,
  "workflow_adherence_v2": { "scenario-uuid-1": 20, "scenario-uuid-2": 50 }
}
```

## Node types

<img
  src="/images/workflows.png"
  alt="Scenario graph: start node, agent and user turns, an options branch, and leaf nodes. Each start-to-leaf path becomes one Digital Human."
  style={{ maxWidth: '100%', borderRadius: '0.5rem' }}
/>

| Node `type` | Description |
|---|---|
| `start` | The entry point. A graph has exactly one start node. It has no `data`. |
| `single` | One turn from the agent or the user. `data.speaker` is `agent` (default) or `user`. |
| `options` | A branch point for the user, for example "press 1 or say billing". Set `data.speaker` to `user`. |

### `single` node `data.type`

| `data.type` | Speaker | Required field |
|---|---|---|
| `message` | agent | `criteria`: what the agent must say, in its own words. Or `exact_match_text`: the exact words. If you set both, `exact_match_text` wins. |
| `message` | user | `intent`: what the Digital Human must say, in its own words. Or `exact_message`: the exact words. |
| `silence` | user only | `duration_ms`: 0 to 86,400,000. |
| `dtmf` | agent or user | `digits`: `0-9`, `*`, `#`, `A-D` (not case-sensitive), or a `{{trait}}` token. |

The types `exact` and `contextual`, and the field `message`, are removed. Bluejay rejects a graph that uses them.

### `options` node

`data.branch_options` has two or more entries. Each entry has a non-empty `id`, `speaker` set to `user`, and a `type` of `message`, `silence`, or `dtmf` with the matching field. Each edge out of an options node sets `sourceHandle` to the `id` of its branch.

<img
  src="/images/workflows-option-node.png"
  alt="Options node with two branches. Each outgoing edge sets sourceHandle to a branch id."
  style={{ display: 'block', margin: '0 auto', width: '50%', borderRadius: '0.5rem' }}
/>

<Warning>
If you change a `branch_options[].id`, the edges that use that `sourceHandle` no longer match. Keep branch IDs stable.
</Warning>

## Validation rules

A graph must have one start node and no cycles. Each node must be reachable from the start node.

## Example definition

This create request has one branch.

```json
{
  "name": "Support and Billing Menu",
  "agent_ids": [123],
  "definition": {
    "nodes": [
      { "id": "start", "type": "start", "data": {} },
      { "id": "agent-menu", "type": "single",
        "data": { "type": "message", "speaker": "agent",
                  "exact_match_text": "Press 1 for support, or say billing." } },
      { "id": "user-choice", "type": "options",
        "data": { "speaker": "user", "branch_options": [
          { "id": "branch-support", "speaker": "user", "type": "dtmf", "digits": "1" },
          { "id": "branch-billing", "speaker": "user", "type": "message", "exact_message": "Billing" }
        ] } },
      { "id": "agent-support", "type": "single",
        "data": { "type": "message", "speaker": "agent",
                  "criteria": "Start to troubleshoot the support issue." } },
      { "id": "agent-billing", "type": "single",
        "data": { "type": "message", "speaker": "agent",
                  "criteria": "Answer the billing question." } }
    ],
    "edges": [
      { "id": "e1", "source": "start", "target": "agent-menu" },
      { "id": "e2", "source": "agent-menu", "target": "user-choice" },
      { "id": "e3", "source": "user-choice", "target": "agent-support", "sourceHandle": "branch-support" },
      { "id": "e4", "source": "user-choice", "target": "agent-billing", "sourceHandle": "branch-billing" }
    ]
  }
}
```

This graph has two paths, so it makes two Digital Humans.
