A Digital Human is a simulated customer that calls, texts, or emails your agent during a [simulation](/test/simulations/overview).

## Parts of a Digital Human

| Part | Owns | Field |
|---|---|---|
| Intent | What the caller wants, in one or two sentences | `intent` |
| Success Criteria | One or two outcomes of the agent that the transcript can show | `success_criteria` |
| Role description | Who the caller is and how they behave | `role_description` |
| Traits | Case facts the caller can say, for example a member ID | `traits` |
| Scripted responses | Fixed replies to specific agent lines | `scripted_responses` |
| Behavior | Voice, noise, pace, interruptions, and hangup | See [Configuration](/key-concepts/digital-humans/configuration) |

To add Digital Humans to a simulation, write them one at a time, generate them from the agent context, or upload a CSV. For the CSV format, see [Bulk upload with CSV](/key-concepts/digital-humans/configuration#bulk-upload-with-csv). To use the same set again, group them in a [Community](/key-concepts/communities/overview).

## Write a Digital Human

1. Keep `intent` and `success_criteria` to one or two sentences each.
2. Put grading that applies to every call in a [Custom Metric](/key-concepts/custom-metrics/overview), not in `success_criteria`.
3. Describe the caller in `intent`. If you write "correctly", "appropriately", or "successfully", move that text to `success_criteria`.
4. Ground the case in the agent context: the agent description, the synced [Workflow](/key-concepts/agents/overview#workflow), and the knowledge base.

## Make runs repeatable

Each "if the agent says X, the caller does Y" rule in `intent` is only a suggestion to the model. Move it to a field:

| Need | Field |
|---|---|
| A fixed value, for example a date of birth or order number | `traits` |
| A fixed line, keypad entry, or pause | `scripted_responses` |
| A fixed opening line | `speaks_first_config` |
| The same call on each run | `creativity` from 0.0 to 0.3 |

For exploratory and red team cases, keep `creativity` near the default of 0.7.

Before you create a batch, create one Digital Human, run it, and read the transcript. Bluejay accepts a configuration that has no effect, for example a scripted response that never matches.
