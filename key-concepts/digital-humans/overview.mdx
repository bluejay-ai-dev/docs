A Digital Human can call, text, or email your agent. Each one has a goal, and Bluejay grades whether your agent handled it.

<Transcript
  turns={[
    { role: "agent", t: "00:01", text: "Thanks for calling. Can I have your member ID?" },
    { role: "human", t: "00:04", text: "Sure, it is 4829-3371." },
    { role: "agent", t: "00:09", text: "Thank you. I booked a callback for tomorrow at 10 AM." }
  ]}
  verdict={{ metric: "Success Criteria", pass: true, reason: "The agent verified the member ID and booked a callback." }}
/>

## Persona

<ParamField path="intent" type="string">
  What the caller wants, in one or two sentences. Do not put agent behavior or "if X, do Y" rules here. The UI label is **Description / Intent**.
</ParamField>
<ParamField path="success_criteria" type="string">
  The pass or fail condition: one or two agent outcomes that the transcript can show.
</ParamField>
<ParamField path="role_description" type="string">
  Who the caller is, in one short line, for example "retiree on a family plan". The UI label is **Personality**.
</ParamField>
<ParamField path="scripted_responses" type="object[]">
  Fixed replies to specific agent lines. See [Scripted responses](#scripted-responses).
</ParamField>
<ParamField path="expected_tool_calls" type="object[]">
  Tool calls the agent must make. The UI label is **Tool Adherence**.
</ParamField>
<ParamField path="num_runs" type="integer" default="1">
  How many times this Digital Human runs in each simulation run.
</ParamField>

There is no emotion field. Write the attitude into `role_description`.

## Traits

A trait is a fact that the caller knows and says when the agent asks, for example a member ID or date of birth. A trait keeps the value the same on each run. If you write the value in `intent`, the caller can say a different value on each run.

A trait belongs to one agent. Define it on the **Customer Traits** page, then set its value on each Digital Human.

If `is_sip_header` is `true`, Bluejay also sends the trait as a SIP header on the call. The header name is the trait name with an `X-` prefix.

When you change a trait, select **Update Existing Digital Humans** to apply the change to all Digital Humans of the agent. Otherwise only new Digital Humans get the change.

## Connection

<ParamField path="phone_number" type="string">
  The number of the Digital Human. It must be a number that your organization owns.
</ParamField>
<ParamField path="extension" type="string">
  Keys to send as DTMF after the call connects to an Inbound agent, for example `1,2`. A comma adds a short pause.
</ParamField>
<ParamField path="always_on_mode" type="boolean" default="false">
  If `true`, the Digital Human answers calls on `phone_number`.
</ParamField>

## Scripted responses

A scripted response makes a reply the same on each run. Each item pairs an agent line with a response.

| Field | Values | Notes |
|---|---|---|
| `match_phrase` | string | A line the agent says, for example "Can I have your account number?". A description of agent behavior never matches. |
| `match_type` | `exact`, `context` | `context` matches lines with the same meaning. |
| `response_type` | `phrase`, `dtmf`, `silence`, `audio` | |
| `response_value` | string | Required for `phrase` and `dtmf`. Do not set it for `audio`. `audio` uses `scripted_response_audio_snippet_url`. |
| `occurrence_mode` | `always`, `first_n` | `first_n` needs `occurrence_n`. |

If `scripted_responses_ordered` is `true`, the responses run in list order and each fires once.

## Follow-up SMS

Bluejay can grade the SMS that a voice agent sends after a call.

Set `follow_up_sms_sender_numbers` on the agent to the E.164 numbers that send the SMS. The SMS is graded against `follow_up_sms_success_criteria` on the Digital Human. If it is empty, Bluejay uses `success_criteria`.

Bluejay links an SMS to a call only if the call ended and the SMS arrives within 30 minutes of the end of the call. If the agent has no sender numbers, Bluejay does not grade follow-up SMS.

## Write a good Digital Human

- Test one goal in each Digital Human. Booking, rescheduling, and cancelling are three Digital Humans.
- Write `intent` as what the caller wants. If you write "correctly" or "successfully", move that text to `success_criteria`.
- Write `success_criteria` as an agent outcome that the transcript can show.
- Put grading that applies to every call in a [Custom Metric](/key-concepts/custom-metrics/overview), not in `success_criteria`.

| Field | Do | Do not |
|---|---|---|
| `intent` | "You want to move your dentist appointment to next week." | "Make sure the agent correctly reschedules. If it asks for your date of birth, say March 3, 1980." |
| `success_criteria` | "The agent moved the appointment and confirmed the new date." | "The caller gives the date of birth and stays polite." |

### Make runs repeatable

An "if the agent says X, the caller does Y" rule in `intent` is only a suggestion to the model. Move it to a field:

| Need | Field |
|---|---|
| A fixed value, for example a date of birth | `traits` |
| A fixed line, keypad entry, or pause | `scripted_responses` |
| A fixed opening line | `speaks_first_config` |
| The same call on each run | `creativity` from 0.0 to 0.3 |

Before you create a batch, create one Digital Human, run it, and read the transcript. Bluejay accepts a configuration that has no effect, for example a scripted response that never matches.

To test a phone tree, use the [Scenario Builder](/key-concepts/scenario-builder/overview).
