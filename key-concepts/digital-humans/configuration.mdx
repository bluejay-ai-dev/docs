This page lists each Digital Human field by the tab of the Digital Human editor where you set it. The API and the `create_digital_humans` MCP tool use the same field names.

## Persona

<ParamField path="intent" type="string">
  The scenario, in one or two sentences: what the caller wants. Do not put agent behavior or "if X, do Y" rules here. Leave it empty when `enriched_playback` is set. The UI label is **Description / Intent**.
</ParamField>
<ParamField path="success_criteria" type="string">
  The pass or fail condition for this test: one or two outcomes of the agent that the transcript can show. Put a scored checklist in a [Custom Metric](/key-concepts/custom-metrics/overview).
</ParamField>
<ParamField path="role_description" type="string">
  Who the caller is, in one short line, for example "retiree on a family plan". Identity and attitude only. The UI label is **Personality**.
</ParamField>
<ParamField path="scripted_responses" type="object[]">
  Fixed replies to specific agent lines. See [Scripted responses](#scripted-responses).
</ParamField>
<ParamField path="expected_tool_calls" type="object[]">
  Tool calls the agent must make. Each item has `name`, and optional `parameters` and `output`. The UI label is **Tool Adherence**.
</ParamField>
<ParamField path="name" type="string">
  The caller name. `test_name` is a separate label for the Digital Human.
</ParamField>
<ParamField path="num_runs" type="integer" default="1">
  How many times this Digital Human runs in each simulation run. Minimum 1.
</ParamField>

## Behavior

| Field | UI label | Values | Default |
|---|---|---|---|
| `language`, `accent`, `gender` | Voice | Valid combinations from `get_voice_options` | `en` |
| `custom_voice_id` | Voice | An ElevenLabs cloned voice ID | None |
| `voice_speed` | Voice Speed | `slowest`, `slow`, `normal`, `fast`, `fastest` | `normal` |
| `background_noise` | Background Noise | `none`, about 50 presets, or `custom` | `none` |
| `background_noise_volume` | Background Noise Volume | 0 to 1 | 0.8 |
| `audio_quality` | Audio Quality | `high`, `medium`, `low`, `horrible` | `high` |
| `connection_quality` | Dropouts | `none`, `low`, `medium`, `high` | `none` |
| `verbosity` | Verbosity | `low`, `medium`, `high` | `medium` |
| `fluency` | Fluency | `beginner`, `intermediate`, `native` | `native` |
| `creativity` | Creativity | 0 to 2 | 0.7 |
| `endpointing_delay` | Patience (seconds) | Seconds to wait before a reply | 1.5 |
| `silence_timeout` | No Response Timeout (seconds) | 15 seconds or more | None |
| `interruptions` | Interruptions | None, Probabilistic, Keywords, Contextual | None |
| `speaks_first_config` | Speaks First | See below | Agent speaks first |

For `background_noise="custom"`, set `custom_background_noise_url` to a path from the noise library of your organization.

There is no emotion field. Write the attitude into `role_description`.

To run each Digital Human with other behavior values in the same run, use [Personalities](/key-concepts/digital-humans/personalities).

### Speaks First

`speaks_first_config` has these fields:

- `speaks_first`: if `true`, the Digital Human can open the call.
- `mode`: `ai_generated`, or `custom` with a `message`.
- `dynamic` (default `true`): the Digital Human waits up to 5 seconds for the agent to speak. If the agent speaks first, the Digital Human does not say its message.

<Warning>
  If the agent greets callers and `dynamic` is `true`, a `custom` opening message is never spoken. Set `dynamic` to `false` to always speak it, possibly over the greeting.
</Warning>

## Traits

`traits` are case facts that the caller knows and can say, for example a member ID, date of birth, or order number. Each trait has `trait_name`, `trait_data_type` (`BOOLEAN`, `STRING`, `DATE`, or `NUMBER`), and `value`. Set `is_sip_header` to `true` to send the trait as a SIP header. See [Customer Traits](/key-concepts/customer-traits/overview).

Do not put agent-side data in traits, for example CRM contents or notes for the grader.

## Tools

| Field | UI label | Default | Effect |
|---|---|---|---|
| `allow_end_call_tool` | Allow End Call Tool | `true` | The Digital Human can end the call. |
| `hangup_phrases` | End Conversation (On Trigger Phrases) | None | Agent phrases that end the call. |
| `hangup_instructions` | Override End Conversation Instructions | `default` | Any value other than `default` replaces the built-in hangup behavior. |
| `allow_silence_tool` | Allow Silence Tool | `true` | The Digital Human can stay silent. |
| `silence_tool_instructions` | Silence Tool Instructions | `default` | Custom guidance for when to stay silent. |
| `allow_dtmf_tool` | Allow DTMF Tool | `true` | The Digital Human can send keypad tones. |
| `default_dtmf_or_voiced` | Default Number Submission Mode | `voiced` | Used when the agent does not say how to enter a number. |
| `outbound_text_number` | Send SMS | Agent number | The number the Digital Human texts during a call. |
| `follow_up_sms_success_criteria` | Follow-up SMS success criteria | None | See [Follow-up SMS](#follow-up-sms). |

If the agent says "Enter your ID", the Digital Human always sends DTMF. If the agent says "What is your ID?", it uses `default_dtmf_or_voiced`.

## Connection

<ParamField path="phone_number" type="string">
  The number of the Digital Human. It must be a number that your organization owns.
</ParamField>
<ParamField path="extension" type="string">
  Keys to send as DTMF after the call connects to an Inbound agent. Use `0-9`, `*`, and `#`. A comma adds a short pause, for example `1,2`. Bluejay ignores this field for Outbound agents.
</ParamField>
<ParamField path="always_on_mode" type="boolean" default="false">
  If `true`, the Digital Human answers calls on `phone_number`. `always_on_active` turns it on or off.
</ParamField>
<ParamField path="livekit_metadata" type="object">
  LiveKit configuration for this Digital Human.
</ParamField>

## Scripted responses

A scripted response makes a reply the same on each run. Each item pairs an agent line with a response.

| Field | Values | Notes |
|---|---|---|
| `match_phrase` | string | A line the agent says, for example "Can I have your account number?". A description of agent behavior never matches. |
| `match_type` | `exact`, `context` | `exact` is a fuzzy text comparison with no LLM call. `context` asks an LLM if the two lines mean the same thing. |
| `response_type` | `phrase`, `dtmf`, `silence`, `audio` | |
| `response_value` | string | Required for `phrase` and `dtmf`. Optional for `silence`. |
| `occurrence_mode` | `always`, `first_n` | |
| `occurrence_n` | integer above 0 | Required for `first_n`. |
| `silence_duration` | integer above 0 | Seconds of silence. |
| `scripted_response_audio_snippet_url` | string | The uploaded audio file for `audio`. |

If `scripted_responses_ordered` is `true`, the responses run in list order and each fires once. In this mode, an empty `match_phrase` fires on the next turn of the Digital Human.

## Bulk upload with CSV

![Upload Custom Digital Humans card on the Create Simulation modal](/images/upload-dh-card.png)

<Steps>
  <Step title="Open the upload panel">
    Go to **Simulations > Create Simulation**, select the agent, and select **Upload Digital Humans**.
  </Step>
  <Step title="Get the template">
    Click **Sample CSV** to download `sample_digital_humans.csv`.
  </Step>
  <Step title="Fill in the rows">
    Add one Digital Human for each row. A blank cell uses the simulation default.
  </Step>
  <Step title="Upload">
    Drop the `.csv` file on the upload area, or click to browse.
  </Step>
</Steps>

![CSV upload area with the Sample CSV button](/images/upload-dh-dropzone.png)

The first row that is not empty is the header. Header matching ignores case. Bluejay ignores columns that it does not know and skips blank rows.

| Column | Sets | Values |
|---|---|---|
| `Name` | `name` | If blank, Bluejay generates a name. |
| `Intent` | `intent` | Text |
| `Success Criteria` | `success_criteria` | Text |
| `Role Description` | `role_description` | Text |
| `Phone Number` or `Caller Number` | `phone_number` | A number your organization owns. Otherwise Bluejay skips the row. |
| `Scripted Responses` | `scripted_responses` | A JSON object or array |
| `Scripted Responses In Order` | `scripted_responses_ordered` | `true` or `false` |
| `Creativity` | `creativity` | 0 to 1 |
| `Patience` | `endpointing_delay` | Seconds, 0 or more |
| `No Response Timeout` | `silence_timeout` | Seconds, 0 or more |
| `Voice` | Voice | A voice key, for example `en_british_feminine` |
| `Voice Speed` | `voice_speed` | As in [Behavior](#behavior) |
| `Background Noise` | `background_noise` | As in [Behavior](#behavior) |
| `Background Noise Volume` | `background_noise_volume` | 0 to 1 |
| `Audio Quality` | `audio_quality` | As in [Behavior](#behavior) |
| `Dropouts` | `connection_quality` | As in [Behavior](#behavior) |
| `Verbosity` | `verbosity` | As in [Behavior](#behavior) |
| `Fluency` | `fluency` | As in [Behavior](#behavior) |
| `Interruptions` | `interruptions` | JSON, see below |
| `Speaks First` | `speaks_first_config` | JSON, for example `{"speaks_first": true, "mode": "custom", "message": "Hi, I am calling about my bill."}` |
| `TC_<tool>` | An expected tool call | A string is the expected output. A JSON object can have `output` and `parameters`. |
| `CT_<trait>` | A trait | The trait value |

The `Interruptions` cell is a JSON object with `interruptions_type`:

- `{"interruptions_type": "none"}`
- `{"interruptions_type": "probabilistic", "probability_of_default_interrupt": 0.5}`, with a value from 0 to 1.
- `{"interruptions_type": "keyword", "keyword_responses": {"refund": {"response": "Yes, the refund!", "probability": 0.8}}}`
- `{"interruptions_type": "llm", "llm_prompt": {"user_prompt": "Interrupt when the agent talks too long."}}`

You cannot add `audio` scripted responses with a CSV. Add them in the editor after the upload.

Bluejay reports row errors and imports the rows that are valid. If a JSON cell does not parse, Bluejay tries to repair quotes and line breaks.

<Warning>
  A repaired JSON cell can have the wrong value. If Bluejay shows a "verify these rows" warning, check those Digital Humans before you run the simulation.
</Warning>

## Follow-up SMS

Bluejay can grade the SMS that a voice agent sends after a call. The SMS shows under the call in the run results.

1. Set `follow_up_sms_sender_numbers` on the agent to the E.164 numbers that send the SMS. Use the API or the `update_agent` MCP tool.
2. Optional: set `follow_up_sms_success_criteria` on the Digital Human. If it is empty, Bluejay uses `success_criteria`.
3. Run the simulation.

Bluejay links an SMS to a call when all of these are true:

- The SMS goes to the phone number of the Digital Human.
- The sender is in `follow_up_sms_sender_numbers`.
- The SMS arrives within 30 minutes of the end of the call.
- The call completed. Calls that did not connect are not linked.

If more than one recent call used that number, Bluejay selects the call that matches the SMS content. Bluejay groups more than one SMS for the same call into one entry. If `follow_up_sms_sender_numbers` is empty, the feature is off.
