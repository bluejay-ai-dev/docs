## Overview

Webhooks let you receive real-time HTTP notifications when events occur in your Bluejay simulations and observability logs. Instead of polling, Bluejay sends a POST request to your endpoint whenever a subscribed event fires. See the [Events Webhook reference](/api-reference/webhook/events-webhook) for the full payload schema.

## Security

### Source

All webhook requests originate from `api.getbluejay.ai`. If your endpoint sits behind a firewall or IP allowlist, whitelist that hostname (or its resolved IPs) so our requests can reach you.

### Request headers

Every webhook request includes the following headers:

| Header | Description |
| --- | --- |
| `Content-Type` | Always `application/json`. |
| `User-Agent` | Identifies the request as coming from Bluejay. |
| `X-Bluejay-Signature` | HMAC-SHA256 signature of the raw request body, signed with your webhook's signing secret. Use this to verify the request came from Bluejay. |
| `X-Bluejay-Event` | The event type (for example, `simulation_result_evaluated`). Matches the `type` field in the body. |
| `X-Bluejay-Delivery` | Unique ID for this delivery attempt. Useful for idempotency and log correlation. |

### Verifying requests

1. Read the raw request body (do not re-serialize the JSON — signature verification is byte-sensitive).
2. Compute `HMAC-SHA256(body, signing_secret)` using the signing secret shown in your webhook settings.
3. Compare the hex digest against the `X-Bluejay-Signature` header using a constant-time comparison.

Reject any request whose signature does not match.

### Recommendations

- Always use an HTTPS endpoint.
- Respond within 5 seconds; do heavier work asynchronously.
- Treat deliveries as at-least-once and dedupe on `X-Bluejay-Delivery`.

## Scoping webhooks to agents and folders

When you create a webhook, pick the agents or folders it should listen to. Only events from those agents — or from any agent in the selected folders — will trigger delivery.

- **Select agents** to narrow down to specific agents.
- **Select folders** to include every agent in that folder.
- **Combine both** for granular rules.

## Troubleshooting

**Webhook not triggering**

- Confirm the webhook is enabled.
- Confirm the source agent or folder is in the webhook's scope.
- Confirm the event type is included in the subscription.
- Confirm the endpoint URL is reachable and responds within 5 seconds.
