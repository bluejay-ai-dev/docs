A Customer Trait is a case fact that a Digital Human knows and can say when the agent asks. Examples are a member ID, a date of birth, or an order number.

A fixed trait value makes the call repeatable. If you write the value in `intent`, the model can say a different value on each run.

## Create a Customer Trait

1. Open the **Customer Traits** page.
2. Select the agent.
3. Click **Create**.
4. Enter the name, the data type, and an optional default value.

With the API, send `POST /v1/create-customer-trait` with `agent_id`, `name`, `data_type`, and `default_value`.

## Fields

| Field | Values |
|---|---|
| Name | The name the agent asks for, for example `member_id`. Use the same name across the test suite. |
| Data type | `BOOLEAN`, `STRING`, `DATE` (ISO 8601), or `NUMBER` |
| Default value | The value that new Digital Humans get |

## Set a value on a Digital Human

On the **Traits** tab of a Digital Human, set a value for each trait. With the API, set `traits` on the Digital Human. Each item has `trait_name`, `trait_data_type`, and `value`. If `is_sip_header` is `true`, Bluejay sends the trait as a SIP header and the caller does not say it.

Do not put agent-side data in a trait, for example CRM contents, expected tool arguments, or notes for the grader. Use `expected_tool_calls`, `success_criteria`, or a Custom Metric for those.

## Change a Customer Trait

When you save a change, select one option:

- **Future Digital Humans**: only new Digital Humans get the change.
- **Update Existing Digital Humans**: all Digital Humans of the agent get the new name, type, and value.

With the API, `PUT /v1/update-customer-trait/{trait_id}` with `sync_existing: true` updates existing Digital Humans.
