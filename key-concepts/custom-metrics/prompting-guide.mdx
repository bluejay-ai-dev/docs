A vague prompt can pass one call and fail an almost identical call.

## Rules for all response types

- Write criteria that a reader can answer from the transcript or the audio.
- Test one thing per metric. If two results matter independently, write two metrics.
- Replace words such as "good", "appropriate", or "well" with behavior that you can see in the transcript.
- Write what the metric verifies, not what the agent must do. Agent instructions go in the agent prompt.

## Prompts by response type

<Tabs>
  <Tab title="Pass/Fail">
    State the pass condition and the fail condition. Give one example of each.

    ```
    The metric passes if the agent asked for at least two of: full name,
    date of birth, last four digits of the card, or billing ZIP code,
    BEFORE it shared any account details.

    The metric fails if the agent asked for fewer than two, or shared
    account details first.

    Example pass: agent asked for date of birth and last four, then
    quoted the balance.
    Example fail: agent quoted the balance after it confirmed only the name.
    ```

    Do not write "Did the agent verify and help the customer well?" That prompt tests two behaviors and uses an undefined word.
  </Tab>
  <Tab title="Number">
    Define each level on the scale. Use five levels or fewer. With no definitions, the judge can give a 4 on one call and an 8 on an almost identical call.

    ```
    Rate the clarity of the agent's explanation from 1 to 5.

    1 = Confusing. The customer cannot act on the explanation.
    2 = Partial. The agent used key terms without a definition.
    3 = Adequate. The customer can act, but must guess some steps.
    4 = Clear. The agent named the steps in order.
    5 = Exceptional. The agent named the steps in order and confirmed
        them with the customer.
    ```
  </Tab>
  <Tab title="Text">
    Set a fixed structure and a word limit, so that you can compare outputs across calls. Ask for observations, not opinions.

    ```
    Summarize how the agent handled customer objections.

    Include:
    1. Each objection the customer raised, in order.
    2. The agent's response to each, quoted briefly.
    3. Whether the response resolved the objection (yes, partial, no).

    Keep the response under 120 words.
    ```
  </Tab>
  <Tab title="Categorical">
    Define the evidence for each label. Give one rule for calls that match more than one label. Use seven labels or fewer, and put rare cases in an `other` label.

    ```
    Classify this call into exactly one category.

    - new_order: The customer places an order they did not place before.
    - modify_order: The customer changes or adds to an existing order.
    - order_status: The customer asks where an existing order is.
    - complaint: The customer reports a problem with an order or the service.
    - general_inquiry: The customer asks about hours, locations, menu,
      or prices and does not place or change an order.

    If two categories apply, select the category that used the most call time.
    ```
  </Tab>
  <Tab title="Structured JSON">
    Give each key a type and a definition. Tell the judge to return only the object. Put the same shape in `json_schema`.

    ```
    Return a JSON object with exactly these keys:

    - identity_verified (boolean): true if the agent verified identity with
      at least two factors before it shared account details.
    - disclosure_read (boolean): true if the agent read the recording
      disclosure in the first 15 seconds.
    - flags (string[]): one short sentence for each compliance issue.
      Empty array if there are none.

    Return only the JSON object.
    ```
  </Tab>
</Tabs>

## Dynamic variables

A dynamic variable puts a call-specific value into a metric. Write `{{key}}` in `prompt` or `scoring_guidance`. Before the judge runs, Bluejay replaces each `{{key}}` with the value of `key` in the Conversation `metadata`.

```
Prompt:    Did the agent confirm the account ending in {{account_last_four}}
           for {{customer_name}}?
metadata:  { "customer_name": "Sarah", "account_last_four": "4821" }
Judge sees: Did the agent confirm the account ending in 4821 for Sarah?
```

Each top-level key in the Conversation `metadata` is a variable. With [`/v1/evaluate`](/api-reference/endpoint/evaluate), send the keys in the `metadata` object. With Vapi or Retell, the call metadata that you set in the provider is included.

Example `/v1/evaluate` request:

```json
{
  "agent_id": "your-agent-id",
  "transcript": [...],
  "metadata": {
    "product_name": "Business Pro",
    "monthly_price": "149"
  }
}
```

### Rules

- A key contains only letters, digits, and underscores. `{{customer name}}` and `{{order.id}}` are not replaced.
- Keys are case-sensitive.

<Warning>
If a key is missing, the judge sees `undefined` in the prompt and can give a wrong verdict. Make sure each key in the prompt is in the `metadata` of every Conversation that the metric evaluates.
</Warning>

## Tune a metric

If the verdicts do not match what your team expects, label a sample of Conversations in the [Metrics Lab](/key-concepts/metrics-lab/overview). Then use **Improve** to change the prompt until the verdicts match your labels.
