Many teams build voice agents as **multi-agent workflows**: a root agent that hands off to specialised sub-agents as the conversation progresses (e.g. *Greeting* → *Gather Details* → *Resolve*). Bluejay pulls that workflow in from your provider, renders it as an editable graph in the **Workflow** tab of Agent Settings, and uses it to generate digital humans that test every path through the flow.

<Note>
  Not to be confused with the [Scenario Builder](/key-concepts/scenario-builder/overview), which is Bluejay's native tool for authoring conversation-path graphs from scratch. Workflows sync from your **provider** and stay two-way editable.
</Note>

## What you can do

The **Workflow** tab appears on any agent whose provider supports workflows. From there you can:

- **Visualise** the workflow as a node-and-edge graph.
- **Edit** any node (name, system prompt, and provider-specific fields like voice, model, and tools), add or delete nodes and edges, and click an edge to set its transition condition. The Start node is protected.
- **Sync** (or **Pull**) to fetch the latest workflow from your provider.
- **Push** to send your edits back to the provider.

Sync and Push each replace the destination wholesale, so pick one source of truth at a time.

## Supported providers

| Provider | Sync | Edit + Push | Extras |
|---|---|---|---|
| **ElevenLabs** | ✅ | ✅ | **Branches**: switch between workflow branches and merge back to Main. Simulations always run against Main |
| **Vapi** | ✅ | ✅ | Works for single assistants and **Squads** (multi-assistant workflows) |
| **Retell** | ✅ | ✅ | Conversation-flow agents |
| **Google Dialogflow CX** | ✅ | ✅ | **Versions and environments**: create a version on push, promote versions to an environment, and preview diffs before syncing or pushing. Conflict-aware push warns before overwriting provider-side changes |

## Driving simulations

The **Generate From Workflow** simulation type enumerates every distinct path through the synced workflow (Start → step → step → …) and generates digital humans whose intents naturally drive the agent down each path. Each path becomes its own digital human card with the path visible underneath the success criteria in the Persona tab.

You pick how many digital humans to generate per path. Three discovered paths × four digital humans = twelve scenarios, each tailored to drive its assigned path.

## Typical loop

1. **Sync** the workflow from your provider.
2. **Create a simulation** with **Generate From Workflow** and run it to see which paths pass and fail.
3. **Edit** the failing node's prompt or edge conditions in Bluejay.
4. **Push** the fix back to your provider and re-run.
