Simulations, Conversations, and Custom Metrics all attach to an Agent.

## Create an Agent

<Steps>
  <Step title="Open the dialog">
    In the sidebar, click **+** (**Add agent**).
  </Step>
  <Step title="Describe the agent">
    Enter a **Name**. In **Agent Description / System Prompt**, describe the agent or paste its system prompt.
  </Step>
  <Step title="Set the type and mode">
    Set **Agent type** to **Inbound** or **Outbound**. Set **Mode** to **Voice**, **Text**, or **Email**.
  </Step>
  <Step title="Connect">
    Select the **Voice Connection Type** or **Text Connection Type** and enter its details. Click **Create**.
  </Step>
</Steps>

An Inbound agent receives calls or messages. An Outbound agent starts them. Some platform connections support Inbound only. The integration page for your platform says which types it supports.

## Modes and connections

<Tabs>
  <Tab title="Voice">
    A Digital Human holds a spoken call with the agent. Bluejay records the call, transcribes it, and grades it.

    | Connection type | You provide |
    |---|---|
    | Phone | A phone number |
    | SIP | A SIP URI, or a `dynamic_sip_webhook_url` that returns the URI for each call |
    | Websocket | A websocket URL, with an optional username and password |
    | A voice platform or framework | The fields on its integration page |

    A voice run also reports built-in audio metrics, for example **Agent Latency**.

    If your agent runs on a supported voice platform, connect the platform once and sync your agents. See your platform page under **Integrations**, for example [Vapi](/integrations/vapi).
  </Tab>
  <Tab title="Text">
    A Digital Human exchanges messages with the agent. Bluejay grades the run from the transcript.

    | Connection type | How it works |
    |---|---|
    | SMS | The Digital Human texts the agent's phone number. |
    | HTTP Webhook | Bluejay sends a POST with each Digital Human message to your webhook URL. Your endpoint replies through the send-http-text-message endpoint. |
    | OpenAI-compatible | Bluejay calls your API base URL with an optional API key and model. |
    | A chat platform | The fields on its integration page. |

    For the HTTP Webhook, send the same `simulation_result_id` on each reply. See [Chat Testing](/simulation-integrations/http-webhooks).
  </Tab>
  <Tab title="Email">
    A Digital Human sends a real email to the agent inbox. The agent replies, and Bluejay grades the thread. Enter the agent email address. If the agent replies from other addresses, add them too.

    <video controls muted playsInline preload="metadata" className="w-full rounded-xl" src="/videos/email-create-agent.mp4"></video>

    Each Digital Human sends from its own address on `mail.bluejaysims.com`. Email runs take longer than voice or SMS runs.

    <Warning>
      Corporate mail (Google Workspace, Microsoft 365) quarantines mail from unknown senders. If you do not allowlist `mail.bluejaysims.com` in the agent inbox, the agent never receives the test and every check fails.
    </Warning>

    <AccordionGroup>
      <Accordion title="Google Workspace">
        1. In the Admin console, open **Apps > Google Workspace > Gmail > Spam, phishing, and malware**.
        2. Under **Email allowlist**, add a rule that bypasses spam for `mail.bluejaysims.com`.
        3. Save.
      </Accordion>
      <Accordion title="Microsoft 365">
        1. In Microsoft 365 Defender, open **Policies & rules > Threat policies > Anti-spam**.
        2. Add `mail.bluejaysims.com` to the allowed domains, or add a mail flow rule that bypasses spam filtering for that domain.
        3. Save.
      </Accordion>
    </AccordionGroup>

    If a test email does not arrive, look in the admin quarantine first.

    <video controls muted playsInline preload="metadata" className="w-full rounded-xl" src="/videos/email-run-sim.mp4"></video>

    Bluejay grades each agent reply with the **SPF**, **DKIM**, **DMARC**, **Spam**, and **Bounced** metrics.

    <video controls muted playsInline preload="metadata" className="w-full rounded-xl" src="/videos/email-metrics.mp4"></video>

    For an Outbound email agent, your agent sends the first email. Each Digital Human waits for an email at its own address, then replies.

    To check an email agent on a schedule, use [Uptime Monitoring](/monitor/uptime/overview). The minimum interval for email is 30 minutes.

    <video controls muted playsInline preload="metadata" className="w-full rounded-xl" src="/videos/email-uptime.mp4"></video>
  </Tab>
</Tabs>

## Outbound trigger webhook

For an Outbound agent, your system starts each conversation. Some voice platforms place the call for Bluejay. Their integration pages say so.

1. Set `outbound_trigger_webhook_url`.
2. Set `outbound_trigger_payload_template` to a JSON body with tokens.
3. When a run starts, Bluejay sends a POST with the filled template to your webhook.
4. Your system calls or messages the Digital Human.

Tokens are `{{digital_human.id}}`, `{{digital_human.name}}`, `{{digital_human.phone_number}}`, `{{digital_human.email}}`, `{{digital_human.intent}}`, and `{{sim_conversation_id}}`.

## Workflow

A Workflow is the multi-agent graph of a provider agent, for example a root agent that hands off to sub-agents. Use the **Workflow** tab of Agent Settings to see and edit that graph, and to test each path through it.

<Note>
  A Workflow is different from a [Scenario](/key-concepts/scenario-builder/overview). You build a Scenario in Bluejay. A Workflow comes from your provider.
</Note>

**Pull** copies the graph from your provider into Bluejay. **Push** sends your Bluejay edits to the provider.

<Warning>
  Push changes the agent in your provider account. If that version is live, real callers get the change. Pull replaces Bluejay edits that you did not push.
</Warning>

To import a graph from a document, attach the document in a **Bluejay AI** chat and ask for a workflow. After you approve the draft, Bluejay AI saves it to the agent. You can import only to an agent that has no workflow provider. An imported workflow has no Pull or Push. Edit it in Bluejay, or import an updated document.

The **Generate From Workflow** simulation type creates Digital Humans that drive the agent down each path.
