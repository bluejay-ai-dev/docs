An Agent is the voice, text, or email system that Bluejay tests and monitors. Simulations, Conversations, Custom Metrics, and Workflows all attach to one Agent.

## Create an Agent

<Steps>
  <Step title="Open the dialog">
    On the **Agents** view, click **+**. The **Connect Your Agent** dialog opens.
  </Step>
  <Step title="Describe the agent">
    Enter a **Name**. In **Agent Description / System Prompt**, describe the agent or paste its system prompt.
  </Step>
  <Step title="Set the type and mode">
    Set **Agent type** to **Inbound** or **Outbound**. Set **Mode** to **Voice**, **Text**, or **Email**.
  </Step>
  <Step title="Connect">
    Select the connection type and enter its details. Click **Create**.
  </Step>
</Steps>

An Inbound agent receives calls or messages. An Outbound agent starts them. With the API, use [Add Agent](/api-reference/endpoint/add-agent) or the `add_agent` MCP tool. The `name`, `system_prompt`, `knowledge_base`, and `goals` fields are required.

## Modes and connections

<Tabs>
  <Tab title="Voice">
    A Digital Human holds a spoken phone call with the agent. Bluejay records the call, transcribes it, and grades it. Set `mode="VOICE"`.

    | Connection type | You provide |
    |---|---|
    | Phone | A phone number |
    | SIP | A SIP URI, or a `dynamic_sip_webhook_url` that returns the URI for each call |
    | Websocket | A websocket URL, with an optional username and password |
    | LiveKit | API key, API secret, host URL, and agent name |
    | Pipecat | API key and agent name |
    | ElevenLabs, Retell, VAPI, Bland | The provider API key and the agent, assistant, or pathway ID |
    | Amelia, Google CES, Dialogflow CX, Sierra | The provider connection fields |

    A voice run reports built-in audio metrics next to your Custom Metrics. Examples are **Agent Latency**, **Agent Interruption Count**, **Avg Agent WPM**, **Agent Speaking %**, and **Agent Audio Clarity**. To start a run, use `queue_simulation_run` with `channel="voice"`.

    For provider setup, see [Retell](/integrations/retell), [ElevenLabs](/integrations/eleven-labs), [Vapi](/integrations/vapi), and [Bland](/integrations/bland).
  </Tab>
  <Tab title="Text">
    A Digital Human exchanges messages with the agent. There is no audio. Bluejay grades the run from the transcript. Set `mode="TEXT"`.

    | Connection type | How it works |
    |---|---|
    | SMS | The Digital Human texts the agent's phone number. |
    | HTTP Webhook | Bluejay sends a POST with each Digital Human message to your webhook URL. Your endpoint replies through the send-http-text-message endpoint. |
    | OpenAI-compatible | Bluejay calls your API base URL with an optional API key and model. |
    | Kore.ai, Amelia, Google CES, Dialogflow CX, Bland | The provider chat connection fields. |

    For the HTTP Webhook, send the same `simulation_result_id` on each reply. See [Chat Testing](/simulation-integrations/http-webhooks). To start a run, use `queue_simulation_run` with `channel="sms"` or `channel="http_text"`.
  </Tab>
  <Tab title="Email">
    A Digital Human sends a real email to the agent inbox. The agent replies, and Bluejay grades the thread. Set `mode="EMAIL"`, `connection_type="EMAIL"`, and `email_address`. If the agent replies from other addresses, list them in `email_reply_addresses`.

    <video controls muted playsInline preload="metadata" className="w-full rounded-xl" src="/videos/email-create-agent.mp4"></video>

    Each Digital Human sends from its own address on `mail.bluejaysims.com`. Email turns take minutes, so runs stay open longer than voice or SMS. To start a run, use `queue_email_simulation_run`.

    <Warning>
      Corporate mail (Google Workspace, Microsoft 365) quarantines mail from unknown senders. If you do not allowlist `mail.bluejaysims.com` in the agent inbox, the agent never receives the test and every check fails.
    </Warning>

    <AccordionGroup>
      <Accordion title="Google Workspace">
        1. In the Admin console, open **Apps > Google Workspace > Gmail > Spam, phishing, and malware**.
        2. Under **Email allowlist**, add a rule that bypasses spam for `mail.bluejaysims.com`.
        3. Save.
      </Accordion>
      <Accordion title="Microsoft 365">
        1. In Microsoft 365 Defender, open **Policies & rules > Threat policies > Anti-spam**.
        2. Add `mail.bluejaysims.com` to the allowed domains, or add a mail flow rule that bypasses spam filtering for that domain.
        3. Save.
      </Accordion>
    </AccordionGroup>

    If a test email does not arrive, look in the admin quarantine first.

    <video controls muted playsInline preload="metadata" className="w-full rounded-xl" src="/videos/email-run-sim.mp4"></video>

    Bluejay writes these metrics on each agent reply:

    | Metric | Type | Measures |
    |---|---|---|
    | SPF | Pass/fail | The sender is authorized for the domain. |
    | DKIM | Pass/fail | The message is signed and not changed. |
    | DMARC | Pass/fail | Authentication aligns with the From address. |
    | Bounced | Pass/fail | The reply was delivered. |
    | Spam | Score out of 10 | The spam score of the reply. |

    <video controls muted playsInline preload="metadata" className="w-full rounded-xl" src="/videos/email-metrics.mp4"></video>

    For an Outbound email agent, your system sends the first email:

    1. Set `agent_type="OUTBOUND"` and `outbound_trigger_webhook_url`.
    2. In `outbound_trigger_payload_template`, include `{{digital_human.email}}`.
    3. When a run starts, Bluejay sends a POST to your webhook with the filled template.
    4. Your system emails the Digital Human at that address.

    Other template tokens are `{{digital_human.intent}}`, `{{digital_human.name}}`, and `{{sim_conversation_id}}`.

    An email uptime monitor checks Agent Responds, Agent Malfunction, Authentication, SPF, DKIM, DMARC, Spam, Bounced, and Latency. Latency is reported, not graded. The minimum interval is 30 minutes. See [Uptime Monitoring](/monitor/uptime/overview).

    <video controls muted playsInline preload="metadata" className="w-full rounded-xl" src="/videos/email-uptime.mp4"></video>
  </Tab>
</Tabs>

## Workflow

A Workflow is the multi-agent graph of a provider agent, for example a root agent that hands off to sub-agents. Bluejay syncs it from the provider and shows it on the **Workflow** tab of Agent Settings. A Vapi Squad shows the tab as **Squad**.

<Note>
  A Workflow is different from a [Scenario](/key-concepts/scenario-builder/overview). You build a Scenario in Bluejay. A Workflow comes from your provider.
</Note>

On the Workflow tab you can edit nodes, prompts, and edge conditions, add or delete nodes and edges, and send the change back. The Start node is protected. Sync and Push each replace the full destination graph. The MCP tools are `sync_agent_workflow` and `push_agent_workflow`.

<Warning>
  Push makes the change live for real callers of the agent. Sync deletes Bluejay edits that you did not push.
</Warning>

| Provider | Sync | Edit and push | Notes |
|---|---|---|---|
| ElevenLabs | Yes | Yes | Branches. You can merge a branch into Main. Simulations run against Main. |
| Vapi | Yes | Yes | Single assistants and Squads. |
| Retell | Yes | Yes | Conversation-flow agents. |
| Dialogflow CX | Yes | Yes | Pull and Push in the editor. Push can create a version and promote it to an environment. |
| Amelia | Yes | Yes | One flow for each agent, selected by name. See [Amelia](/integrations/amelia). |
| Bland | Yes | Yes | Pathways. Prompt edits go to the live draft. Edge changes go to a new pathway version. |
| Imported | No | Edit only | A graph imported from a document. It opens read-only until you click Edit. |

The **Generate From Workflow** simulation type lists each path through the Workflow. It creates Digital Humans that drive the agent down each path. You set how many Digital Humans to create for each path. See [ElevenLabs](/integrations/eleven-labs) for a full example.
