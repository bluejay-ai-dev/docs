Bluejay can test an email agent the same way it tests voice and SMS: a Digital Human sends a real email to your agent's inbox, your agent replies, and Bluejay grades the exchange. The whole conversation runs over real email, so you are testing the actual channel your customers use, not a stand-in.

## How it works

1. You create an agent with the **Email** connection type and give it the inbox your agent answers from (for example `support@yourcompany.com`).
2. When a simulation runs, the Digital Human emails that inbox from a per-test address on Bluejay's managed sending domain, `mail.bluejaysims.com`.
3. Your agent replies over email.
4. Bluejay receives the reply, threads it into the conversation, and continues until the exchange ends, then grades it against your success criteria like any other run.

Correlation is automatic: each test sends from a unique per-test address, so replies always attach to the right conversation.

## Create an email agent

In the app, create an agent, choose **Text**, then the **Email** connection type, and enter the agent's email address.

<Warning>
  The agent's inbox must **allowlist Bluejay's sending domain** (`mail.bluejaysims.com`). Corporate mail systems (Google Workspace, Microsoft 365, on-prem gateways) quarantine mail from unfamiliar senders before it reaches the mailbox, so without an allowlist entry your agent never receives the test and every check fails. Consumer inboxes (Gmail, Outlook.com) usually deliver without this step.
</Warning>

### Allowlist Bluejay's sending domain

Every probe email comes from `mail.bluejaysims.com`. Add it to the receiving inbox's allowlist so the test email is delivered instead of quarantined.

**Google Workspace**
1. Admin console → **Apps → Google Workspace → Gmail → Spam, phishing, and malware**.
2. Under **Email allowlist**, add an **Inbound gateway** or content-compliance rule that bypasses spam for `mail.bluejaysims.com`.
3. Save. Delivery takes effect within a few minutes.

**Microsoft 365 (Exchange Online)**
1. Microsoft 365 Defender → **Policies & rules → Threat policies → Anti-spam**.
2. Add `mail.bluejaysims.com` to the **Allowed senders / domains** list, or create a mail-flow rule that sets the spam confidence level to bypass for that domain.
3. Save.

If a test email does not arrive, check your admin quarantine first, the message is almost always held there, not lost.

## Run an email simulation

Build a simulation on the email agent, add Digital Humans, and run it. Bluejay sends each Digital Human's opening email, drives the back-and-forth, and grades the result. Email turns take minutes rather than seconds, so runs stay open longer than voice or SMS.

## Checks on every reply

Alongside your success criteria, Bluejay runs six deterministic checks on each reply from your agent. Five are pass or fail; the sixth is measured and reported.

| Check | What it measures |
|-------|------------------|
| **SPF** | The reply passed sender authentication |
| **DKIM** | The reply carried a valid message signature |
| **DMARC** | The reply passed the sending domain's alignment policy |
| **Spam** | The reply was not placed in spam |
| **Bounced** | The reply was delivered rather than bounced |
| **Round-trip latency** | Time from the Digital Human's send to your agent's reply, reported not thresholded |

SPF, DKIM, and DMARC together tell you whether your agent's mail authenticates cleanly. Round-trip latency is recorded for every reply so you can see how long your agent takes to respond, but it does not pass or fail on its own.

## Outbound: your agent emails first

By default the Digital Human emails your agent (inbound). For an **outbound** agent, your own system sends the first email and Bluejay's Digital Human replies, the same trigger-webhook model as outbound voice and SMS.

1. Create the agent with type **Outbound** and set its **outbound trigger webhook URL** (and, optionally, a payload template).
2. When a simulation runs, Bluejay does not send an opening email. Instead it POSTs your trigger webhook so your flow knows to start the conversation.
3. Your flow emails the Digital Human at the address Bluejay provides, and the Digital Human replies and is graded from there.

The trigger payload is your template with `{{tokens}}` filled in. The key token for email is **`{{digital_human.email}}`**, the unique per-test address your flow must email so the reply reaches the right Digital Human (for example `monitor+12345@mail.bluejaysims.com`). Other tokens include `{{digital_human.intent}}`, `{{digital_human.name}}`, and `{{sim_conversation_id}}`. With no template, Bluejay sends a minimal default.

## Email uptime monitors

An uptime monitor runs the same send-and-reply loop on a schedule against a live email agent, so you find out the channel has broken before your customers do. On each run the Digital Human emails your agent, waits for the reply, and grades it.

<video autoPlay muted loop playsInline className="w-full rounded-xl" src="/videos/email-uptime.mp4"></video>

Email monitors grade:

| Check | What it measures |
|-------|------------------|
| **Agent Responds** | Your agent replied within the interval |
| **Authentication** | The reply passed SPF, DKIM, and DMARC |
| **Spam** | The reply was not placed in spam |
| **Bounced** | The reply was delivered rather than bounced |
| **Round-trip latency** | Time from send to reply, reported so you can watch it trend |

Email conversations run for minutes, so pick a comfortably long interval. See [Uptime Monitoring](/monitor/uptime/overview) for scheduling, alerting, and verdict rules.

## Set it up with the API or MCP

Email agents and runs are fully scriptable.

- Create the agent with **add-agent**: `mode="TEXT"`, `connection_type="EMAIL"`, and `email_address` set to the agent's inbox. Over MCP this is the `add_agent` tool with the same fields.
- For an outbound email agent, also set `type="OUTBOUND"`, `outbound_trigger_webhook_url`, and (optionally) `outbound_trigger_payload_template` with `{{digital_human.email}}` so your flow receives the address to email.
- Queue a run with **queue-email-simulation-run** (MCP tool `queue_email_simulation_run`), passing the `simulation_id`.

Everything else, creating the simulation, adding Digital Humans, reading results, uses the same tools as any other medium.
