The simulation result ID can be found as a header of the websocket connect message. The header will look like this: 

`X-Simulation-Result-Id: <simulation_result_id>`

This ID associates your tool calls, events, tags, and metadata with the specific simulation result.
Given this ID, this endpoint updates your simulation result to enrich the simulation with the tool calls, events, tags, and metadata you provide.

If you do not have the ID, send `start_time`, `end_time`, and `duration` (seconds) instead. Bluejay looks in the workspaces your key can see for a connected simulation. A call whose duration is not stored yet stays in that set. When duration is stored, the stored start is compared to `start_time` and the end (stored start plus stored duration) is compared to `end_time`; both must fall within 90 seconds, and the stored duration must be within the larger of 5 seconds and 10% of `duration`.

When you omit `recorded_transcript`, exactly one call must match the window; that call is updated. When you include it, every call in the window is scored: one call is kept only when the transcript shares at least 80% of its normalized words, and several calls are separated only when the closest transcript leads the next one by a clear margin. If more than one call is in the window and the transcript does not separate them, the response is `409` and nothing is written.

`404` means nothing in your organization matched the window. `409` means the transcript was missing, not stored yet, too close to separate the calls, or not close enough to the only call in the window. Send `simulation_result_id` in that case.
