[JSON will be deprecated](/key-concepts/bluejay-as-code/overview#move-from-json-to-yaml) on November 20th, 2026.
</Warning>

Applies a bundle. Bluejay matches each item by `bluejay_as_code_id`:

- No match: Bluejay creates the item.
- Match with changed fields: Bluejay updates the item.
- Match with the same fields: no change.

Digital Humans that are not in the bundle are unlinked from the simulation. Custom metrics that are not in the bundle are unlinked from the agent. The response lists each action as text.

<Warning>
  If you generate new `bluejay_as_code_id` values for each push, Bluejay creates duplicate items. Keep the values stable in your config.
</Warning>

Bluejay reads the body as YAML when `Content-Type` is one of these types:

- `application/yaml`
- `application/x-yaml`
- `text/yaml`
- `text/x-yaml`

Any other `Content-Type` is read as JSON. Unreadable YAML, or YAML with anchors and aliases (`&`, `*`), returns HTTP `400`.

Use `--data-binary`, since `--data` strips the line breaks YAML needs:

```bash
curl --request POST \
  --url https://api.getbluejay.ai/v1/bluejay-as-code \
  --header "X-API-Key: $BLUEJAY_API_KEY" \
  --header "Content-Type: application/yaml" \
  --data-binary @simulation.yaml
```
