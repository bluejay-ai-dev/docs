The Bluejay REST API takes and returns JSON. To find an endpoint, use the sidebar or the [cheat sheet](/api-reference/cheat-sheet).

## Make your first request

<Steps>
  <Step title="Get an API key">
    Open the [API Keys page](https://app.getbluejay.ai/settings/api-keys) of the app and create a key. The API ignores the `X-Organization-Id` header.
  </Step>
  <Step title="Send a request">
    Send every request to the base URL `https://api.getbluejay.ai`, with the key in the `X-API-Key` header. All endpoint paths start with `/v1`. This request lists the agents your key can reach:

    ```bash
    curl https://api.getbluejay.ai/v1/all-agents \
      -H "X-API-Key: YOUR_API_KEY"
    ```
  </Step>
  <Step title="Read the response">
    A successful request returns a `2xx` status and a JSON body. This request returns a list of agents, and each item has the agent's `id`, which other endpoints take as `agent_id`. Each endpoint page shows the fields of its response and an example. If the request fails, read the status code and the `detail` field, as [Errors](#errors) explains.
  </Step>
</Steps>

To try an endpoint without writing code, use the [API Playground](/api-reference/playground).

## Errors

When a request fails, the response has an HTTP status code and a JSON body whose `detail` field explains the problem:

```json
{ "detail": "Agent not found" }
```

<div className="table-fit">

| Status | Meaning |
|---|---|
| 400 | The request is not valid for the current state, for example a delete that a rule blocks. |
| 401 | The API key is missing, not valid, or revoked. |
| 402 | The organization needs a payment method. `code` is <Code>NO_PAYMENT_METHOD</Code> or <Code>RED_TEAMING_PAYMENT_METHOD_REQUIRED</Code>. |
| 403 | The resource is not in your organization or workspace. `code` is <Code>INSUFFICIENT_CREDITS</Code> or <Code>SPEND_ALERT_REACHED</Code> when billing blocks the request. |
| 404 | The resource does not exist. |
| 409 | The request conflicts with current data, for example a duplicate. |
| 422 | A field failed validation. `detail` is a list of items with `loc`, `msg`, and `type`. |
| 429 | The rate limit is exceeded. The body is `{"error": "Rate limit exceeded: ..."}`. |
| 503 | Authentication is not available for a short time. Send the request again. |

</div>

When billing blocks a request, the body also has a `code` field next to `detail`:

```json
{ "detail": "...", "code": "INSUFFICIENT_CREDITS" }
```

## Pagination

A list endpoint that can return many rows splits them into pages, using one of three styles. Each endpoint page shows its parameters, defaults, and maximum values.

<div className="table-fit">

| Style | Parameters | Example endpoints |
|---|---|---|
| Page | `page` (starts at 1) and `page_size` | [Get All Digital Humans](/api-reference/endpoint/get-all-digital-humans), [List conversations](/api-reference/endpoint/list-conversations) |
| Offset | `limit` and `offset` | [List Issues](/api-reference/endpoint/list-issues), [Retrieve Simulation Results](/api-reference/endpoint/retrieve-simulation-results) |
| Limit | `limit` only | [List Traces](/api-reference/endpoint/list-traces), [List Agent Versions](/api-reference/endpoint/list-prompt-versions) |

</div>

Other list endpoints return all rows in one response.

## Rate limits

Endpoints with a rate limit allow 100 requests per minute from each client IP address, unless the end of the endpoint page shows a different limit.

[Evaluate](/api-reference/endpoint/evaluate) counts requests for your whole organization instead of for each IP address. It allows 100 requests per minute, or 500 for enterprise accounts.

If you go over a limit, the request returns 429. Wait until the next minute, then send the request again.
