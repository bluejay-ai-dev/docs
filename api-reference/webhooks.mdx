A webhook sends Bluejay events to your server. When an event occurs, for example when a simulation finishes evaluation, Bluejay sends a `POST` request with a JSON body to a URL that you give. The [Events Webhook reference](/api-reference/webhook/events-webhook) has the payload of each event.

## Set up a webhook

<Steps>
  <Step title="Make an endpoint on your server">
    Add a route on your own server that accepts a `POST` request with a JSON body, for example `https://api.example.com/bluejay-events`. Bluejay sends events to this URL. It must use HTTPS and be reachable from the internet.

    To test before you write any code, use a free request inspector such as [webhook.site](https://webhook.site). It gives you a URL and shows each request that it gets.
  </Step>
  <Step title="Add the webhook in Bluejay">
    Open **Settings → Webhooks** in the [workspace](/administration/workspaces) whose agents you want to watch, and click **Create new webhook**. Enter your URL and select the events you want.

    To watch only some agents, select them under **Agents & Folders**. A folder includes every agent in it. If you select nothing, the webhook fires for all agents in the workspace. A webhook never fires for agents in a different workspace.
  </Step>
  <Step title="Copy the signing key">
    After you click **Create**, Bluejay shows the signing key one time. Copy it and save it on your server, for example as an environment variable. If you lose it, click the key icon on the webhook row to see it again.
  </Step>
  <Step title="Check the signature on each request">
    Use the signing key to make sure that each request comes from Bluejay. See the next section.
  </Step>
</Steps>

## Verify the signature

Your URL is public, so anyone can send a request to it. The signing key is a secret that only you and Bluejay know. Bluejay uses it to sign the body of each request, and puts the result in the `X-Bluejay-Signature` header. Your server signs the same body with the same key. If the two values match, the request comes from Bluejay and nobody changed it. If they do not match, reject the request.

The signature is the hex HMAC-SHA256 of the raw request body. Sign the raw bytes as you get them. If you parse the JSON and serialize it again, the bytes change and the signature does not match.

```python
import hmac, hashlib

def is_valid(body: bytes, signature: str, signing_key: str) -> bool:
    expected = hmac.new(signing_key.encode(), body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```

## Events

| UI label | `type` in the body | Fires when |
|----------|--------------------|------------|
| Simulation evaluated | <Code>simulation_result_evaluated</Code> | A simulation result finishes evaluation. |
| Simulation run completed | <Code>simulation_run_completed</Code> | Every conversation in a simulation run is evaluated. The body has the run's `pass_rate`. |
| Simulation ended | <Code>simulation_ended</Code> | A simulated conversation ends, before evaluation. |
| Outbound simulation started | <Code>outbound_simulation_started</Code> | An outbound simulation run starts. |
| Observability log evaluated | <Code>observability_call_evaluated</Code> | A production conversation finishes evaluation. |
| Observability alert triggered | <Code>observability_alert_triggered</Code> | An observability [alert](/monitor/alerts) enters or leaves alarm. |
| Simulation alert triggered | <Code>simulation_alert_triggered</Code> | A simulation alert fires or recovers for a run. `subtype` is `triggered` or `recovered`. |

## Delivery

- Requests come from `api.getbluejay.ai`. If you use an allowlist, allow that host.
- Bluejay sends each event once and does not retry.

## Troubleshooting

If a webhook does not fire, do these checks:

1. Make sure the webhook is enabled.
2. Make sure the event is selected.
3. Make sure the agent is in the selected agents or folders.
4. Make sure the agent and the webhook are in the same workspace.
5. Check the tag. If a [`POST /v1/evaluate`](/api-reference/endpoint/evaluate) request sets `webhook_tag`, only webhooks with that tag fire. If it does not, webhooks that have a tag do not fire.
6. Make sure your URL is reachable from the internet.
