Bluejay runs a test conversation with your agent on a schedule and notifies you when it stops working. It works for voice, SMS, and email agents.

## Checks

Checks decide whether a run passes. A monitor needs at least one check that grades something, or Bluejay rejects the monitor.

| Check | Passes when |
|-------|-------------|
| **Agent Responds** | The call connected and the agent kept answering the caller. On a voice call, a silence of more than 15 seconds after the caller speaks fails the check. |
| **Agent Malfunction** | The agent did not state an error during the conversation. |
| **Latency** | The average response time stayed under the threshold. |
| **Custom metric** | One of your custom metrics met its condition. |

Email monitors use different checks:

| Check | Passes when |
|-------|-------------|
| **Agent Responds** | The agent replied. |
| **Agent Malfunction** | The reply did not state an error. |
| **Authentication** | The reply passed SPF, DKIM, and DMARC. |
| **Spam** | The reply was not marked as spam. |
| **Bounced** | The probe email was delivered. |
| **Latency** | Never fails. Bluejay reports the time from send to reply. |

<Warning>
  For email monitors, allowlist `mail.bluejaysims.com` in the agent's inbox. If you do not, Google Workspace or Microsoft 365 can quarantine the probe email, and the agent never receives it.
</Warning>

## Verdicts

| Verdict | Meaning |
|---------|---------|
| **UP** | All measurable checks passed. |
| **DOWN** | At least one check failed. |

Bluejay sends a notification only when the verdict changes between UP and DOWN.

## Latency

Latency is the average time from the end of the caller's turn to the start of the agent's reply. The greeting is not included.

| Channel | Default `latency_threshold_ms` |
|---------|--------------------------------|
| Voice | 3000 |
| SMS and webchat | 60000 |
| Email | No threshold. Bluejay reports the time from send to reply. |

## Alert after repeated failures

To ignore one-off failures, set `alert_after_failures` on a check. The check counts toward DOWN only after that many failures in a row.

```json
{
  "id": "latency",
  "checkType": "latency",
  "enabled": true,
  "config": { "latency_threshold_ms": 3000, "alert_after_failures": 3 }
}
```

Keep **Agent Responds** at the default of 1, so that you are notified at once when your agent stops answering.

## Timeouts

A run fails if it does not finish within its timeout.

| Monitor | Timeout |
|---------|---------|
| Voice | 5 minutes |
| Voice with a custom Digital Human | 10 minutes |
| SMS | 15 minutes |
| Email | 15 minutes |

## Custom caller

To make the probe use one of your Digital Humans, add this entry to the monitor's `checks` array:

```json
{
  "id": "dh-1234",
  "label": "Impatient repeat customer",
  "description": "Digital Human check.",
  "enabled": true,
  "isTemplate": false,
  "digitalHumanId": "1234"
}
```

The Digital Human entry only selects the caller and grades nothing, so the monitor still needs at least one enabled check with a `checkType` or `customMetricId`. When you update `checks`, send the full array, because the update replaces it.

## Outbound agents

Bluejay does not call your outbound agent, so your side must start the conversation. To make that happen, set an outbound trigger webhook on the agent. Some voice platforms place the call for Bluejay instead, and their integration pages say so. If an outbound agent has no way to start the call, Bluejay rejects the monitor.

An outbound email agent needs only its inbox address, because it sends the first email.
