title: 'Uptime Monitoring'
description: 'Run a scheduled health check against a live voice, SMS, or email agent, record UP or DOWN, and send a notification when it changes.'

---

An uptime monitor calls, texts, or emails one of your live agents on a schedule. It grades the result as UP, DOWN, or UNKNOWN, and sends a notification when the verdict changes between UP and DOWN. It works for voice, SMS, and email agents, inbound and outbound.

## Checks

A monitor must have at least one check that grades something. If it has none, Bluejay rejects the monitor.

| Check | Passes when |
|-------|-------------|
| **Agent Responds** | The call connected and the agent spoke. |
| **Agent Malfunction** | The agent did not state an error during the conversation. |
| **Latency** | The average response time stayed under the threshold. |
| **Custom metric** | One of your Custom Metrics met its condition. |

Email monitors use different checks:

| Check | Passes when |
|-------|-------------|
| **Agent Responds** | The agent replied. |
| **Authentication** | The reply passed SPF, DKIM, and DMARC. |
| **Spam** | The reply was not marked as spam. |
| **Bounced** | The probe email was delivered. |
| **Latency** | The time from send to reply stayed under the threshold. |

<Warning>
  For email monitors, allowlist `mail.bluejaysims.com` in the agent's inbox. If you do not, Google Workspace or Microsoft 365 can quarantine the probe email, and the agent never receives it.
</Warning>

## Verdicts

| Verdict | Meaning |
|---------|---------|
| **UP** | All measurable checks passed. |
| **DOWN** | At least one check failed. |
| **UNKNOWN** | Nothing could be measured. |

Uptime percentage is UP divided by (UP + DOWN). UNKNOWN does not count. Notifications fire only on a change between UP and DOWN. UNKNOWN never sends a notification.

## Latency

Latency is the time from the end of the caller's turn to the start of the agent's reply, averaged across the conversation. The agent's greeting is not included. Agent Responds covers the greeting.

| Channel | Default `latency_threshold_ms` |
|---------|--------------------------------|
| Voice | 3000 |
| SMS and webchat | 60000 |
| Email | Measured from send to reply. Set a value for your agent. |

## Alert after repeated failures

One slow conversation or one Agent Malfunction verdict can be noise. Set `alert_after_failures` on a check so it counts toward DOWN only after that many failures in a row. One pass resets the count.

```json
{
  "id": "latency",
  "checkType": "latency",
  "enabled": true,
  "config": { "latency_threshold_ms": 3000, "alert_after_failures": 3 }
}
```

Keep Agent Responds at the default of 1. An agent that does not answer must send a notification at once.

## Frequency and timeouts

Select a frequency from every 1 minute to every hour. The default is every 5 minutes. A check that does not finish in time is UNKNOWN.

| Monitor | Timeout |
|---------|---------|
| Voice | 5 minutes |
| Voice with a custom Digital Human | 10 minutes |
| SMS | 15 minutes |
| Email | 15 minutes |

## Custom caller

To make the probe use one of your Digital Humans, add this entry to the monitor's `checks` array:

```json
{
  "id": "dh-1234",
  "label": "Impatient repeat customer",
  "description": "Digital Human check.",
  "enabled": true,
  "isTemplate": false,
  "digitalHumanId": "1234"
}
```

A Digital Human only selects the caller. It grades nothing, so keep at least one enabled check with a `checkType` or `customMetricId`. `checks` replaces the full array on [Update Uptime Monitor](/api-reference/endpoint/update-uptime-monitor). To go back to the default caller, send the checks without the `digitalHumanId` entry.

## Outbound agents

Bluejay does not call your outbound agent. Your side must start the conversation. Use Vapi or Retell to place the call, or set your own outbound trigger webhook. If an outbound agent has neither, Bluejay rejects the monitor.

## API and MCP

The [REST API](/api-reference/endpoint/create-uptime-monitor) and the [MCP tools](/mcp/overview#uptime-monitors) can create, update, pause, resume, and delete monitors. Updates are partial. Send only the fields you change.
