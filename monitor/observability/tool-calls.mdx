Tool calls, events, and metadata give Custom Metrics the actions your agent took during a conversation, in addition to the transcript.

## Send tool calls

<Tabs>
  <Tab title="Simulations">
    Bluejay sends an `X-Simulation-Result-Id` with each simulated call. Your agent reads it, records its tool calls during the call, and sends them after the call ends.

    | Connection | Where the ID arrives |
    |------------|----------------------|
    | [SIP](/simulation-integrations/sip) | A custom header on the SIP INVITE. |
    | [WebSocket](/simulation-integrations/websockets) | A header on the WebSocket upgrade request. |
    | [LiveKit](/integrations/livekit) | A participant attribute. |

    A plain phone number connection sends no ID, so it cannot attach tool calls. Use SIP for phone agents.

    After the call ends, send the data to [`POST /v1/update-simulation-result`](/api-reference/endpoint/update-simulation-result):

    ```json
    {
      "simulation_result_id": "1234",
      "tool_calls": [
        {
          "name": "transfer_funds",
          "parameters": { "from": "12345", "to": "67890", "amount": 500 },
          "output": { "transaction_id": "txn_abc123", "status": "completed" },
          "start_offset_ms": 120000
        }
      ],
      "events": [
        { "title": "Customer verified", "start_offset_ms": 30000, "tags": ["verification"] }
      ],
      "metadata": { "resolution_status": "resolved" }
    }
    ```

    The same request also accepts `trace_ids`. See [Traces](/key-concepts/traces/overview).

    <Note>
      For LiveKit agents, you can skip the API call. Set **LiveKit Customer Tool Topic** in the agent's connection settings. Then publish a JSON data packet to that topic each time your agent calls a tool. Bluejay saves the packets when the call ends.
    </Note>
  </Tab>
  <Tab title="Production">
    Put `tool_calls`, `events`, and `metadata` in the same [`POST /v1/evaluate`](/api-reference/endpoint/evaluate) request as the transcript or recording. You cannot add them later.

    ```json
    {
      "agent_id": "123",
      "start_time_utc": "2026-07-16T18:00:00Z",
      "participants": [
        { "role": "AGENT", "spoke_first": true },
        { "role": "USER", "spoke_first": false }
      ],
      "recording_url": "https://storage.example.com/call.mp3",
      "tool_calls": [
        {
          "name": "check_order_status",
          "start_offset_ms": 2000,
          "description": "Look up order status by order ID",
          "parameters": { "order_id": "ORD-2024-001" },
          "output": { "status": "in_transit" }
        }
      ],
      "metadata": { "customer_tier": "premium" }
    }
    ```
  </Tab>
</Tabs>

## Tool call fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | The tool name. |
| `start_offset_ms` | integer | Yes | Milliseconds from the start of the conversation. |
| `description` | string | No | What the tool does. Custom Metrics read it. |
| `parameters` | object | No | The input to the tool. |
| `output` | any | No | The value the tool returned. |

## Event fields

An event marks a moment in the conversation, for example an escalation or a hold.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `title` | string | Yes | The event name. |
| `start_offset_ms` | integer | Yes | Milliseconds from the start of the conversation. |
| `end_offset_ms` | integer | No | When the event ended. |
| `description` | string | No | Details of the event. |
| `tags` | string[] | No | Tags for the event. |
| `metadata` | object | No | Extra data for the event. |

## Metadata

`metadata` is a free-form JSON object for the whole conversation. Bluejay puts each key into the matching `{{placeholder}}` in your Custom Metrics. See [Dynamic Variables](/key-concepts/custom-metrics/prompting-guide). Keys that match no placeholder are stored with the conversation and cause no error.
