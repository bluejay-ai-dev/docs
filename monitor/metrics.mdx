## Set up a metric

<img className="block dark:hidden" src="/images/metrics-page.png" alt="The Metrics page with the Create menu open, showing Add from library, Create automatically, and Create manually" />
<img className="hidden dark:block" src="/images/metrics-page-dark.png" alt="The Metrics page with the Create menu open, showing Add from library, Create automatically, and Create manually" />

<Tabs>
  <Tab title="Manual">
<Steps>
  <Step title="Open the form">
    On the **Metrics** page, click **Create**, then **Create manually**.
  </Step>
  <Step title="Write the rule">
    Choose a [metric type](#metric-types). For LLM as a Judge, pick the response type and write the prompt with the [prompting guide](/monitor/metrics/llm-as-a-judge#prompting-guide).

    <img className="block dark:hidden" src="/images/metric-create-dialog.png" alt="The Create Metric dialog with a name and prompt filled in, and the Agents, Evaluates, and Runs on fields set" />
    <img className="hidden dark:block" src="/images/metric-create-dialog-dark.png" alt="The Create Metric dialog with a name and prompt filled in, and the Agents, Evaluates, and Runs on fields set" />
  </Step>
  <Step title="Choose where it runs">
    Select the agents to grade. **Runs on** decides whether the metric grades simulations, production conversations, or both. To grade only some conversations, [add metric conditions](#add-metric-conditions). Then click **Create**.
  </Step>
</Steps>
  </Tab>
  <Tab title="Automatic">
<Steps>
  <Step title="Open the generator">
    On the **Metrics** page, click **Create**, then **Create automatically**.
  </Step>
  <Step title="Pick the agent">
    Bluejay reads the agent's context, such as its system prompt, to write the drafts. It writes 1 to 10 metrics at a time. To steer them, open **Generation instructions (optional)**, for example "Focus on compliance and escalation."
  </Step>
  <Step title="Review and save">
    Click **Generate**, review the drafts, and save the ones you want.
  </Step>
</Steps>
  </Tab>
  <Tab title="API">
<Steps>
  <Step title="Get an API key">
    Open the [API Keys page](https://app.getbluejay.ai/settings/api-keys) of the app and create a key.
  </Step>
  <Step title="Send the metric">
    Send it to [`POST /v1/create-metric`](/api-reference/endpoint/create-custom-metric). Use `agent_ids` to choose the agents it grades.

    ```bash
    curl https://api.getbluejay.ai/v1/create-metric \
      -H "X-API-Key: $BLUEJAY_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "name": "DOB Verified Before PHI",
        "prompt": "The agent verifies the caller'"'"'s date of birth before it discusses patient information.",
        "metric_type": "llm_judge",
        "response_type": "pass_fail",
        "scope": "observability",
        "agent_ids": [123]
      }'
    ```
  </Step>
</Steps>
  </Tab>
  <Tab title="Bluejay as Code">
<Steps>
  <Step title="Pull the agent">
    [Pull](/bluejay-as-code/overview#pull-the-payload) the agent's payload. It includes the custom metrics linked to the agent.
  </Step>
  <Step title="Add the metric">
    Add an item to `custom_metrics` with a new `bluejay_as_code_id`, and add that ID to the agent's `custom_metrics` list.

    ```yaml
    agents:
    - bluejay_as_code_id: f3d2a87c-1e4b-4b9a-9c2d-7f1e6b5a4c33
      custom_metrics:
      - 2b8d4c1f-9a3e-4f72-b5c0-6e1d8a7f3c44
    custom_metrics:
    - bluejay_as_code_id: 2b8d4c1f-9a3e-4f72-b5c0-6e1d8a7f3c44
      name: DOB Verified Before PHI
      prompt: The agent verifies the caller's date of birth before it discusses patient information.
      metric_type: llm_judge
      response_type: pass_fail
      scope: observability
    ```
  </Step>
  <Step title="Push the file">
    [Push](/bluejay-as-code/overview#push-the-payload) the file, and check that `valid` is `true` in the response.
  </Step>
</Steps>
  </Tab>
</Tabs>

## Metric types

| Type | How it scores |
|---|---|
| [LLM as a Judge](/monitor/metrics/llm-as-a-judge) | An LLM scores the conversation against your prompt. |
| [Phrase Match](/monitor/metrics/deterministic) | Checks whether specific words were said. |
| [Tool Call](/monitor/metrics/deterministic) | Passes when the agent called the tools you name. |
| [Transfer Landed](/monitor/metrics/deterministic) | Passes when the Digital Human you choose answers the transfer in time. |
| [Composite](/monitor/metrics/composite) | Combines the results of other metrics into one score or label. |

## Tool calls, events, and metadata

A transcript does not show which tools your agent called. To grade tool calls, send them to Bluejay with the conversation. You can send events and metadata in the same way. `metadata` is a free-form JSON object for the whole conversation, and its keys fill a metric's [dynamic variables](/monitor/metrics/llm-as-a-judge#dynamic-variables).

### Send tool calls

Put `tool_calls`, `events`, and `metadata` in the same [`POST /v1/evaluate`](/api-reference/endpoint/evaluate) request as the transcript or recording, because you cannot add them later.

```json
{
  "agent_id": "123",
  "start_time_utc": "2026-07-16T18:00:00Z",
  "participants": [
    { "role": "AGENT", "spoke_first": true },
    { "role": "USER", "spoke_first": false }
  ],
  "recording_url": "https://storage.example.com/call.mp3",
  "tool_calls": [
    {
      "name": "check_order_status",
      "start_offset_ms": 2000,
      "description": "Look up order status by order ID",
      "parameters": { "order_id": "ORD-2024-001" },
      "output": { "status": "in_transit" }
    }
  ],
  "metadata": { "customer_tier": "premium" }
}
```
