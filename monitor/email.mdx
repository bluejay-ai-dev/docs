## Send a thread

Send the thread to [`POST /v1/evaluate`](/api-reference/endpoint/evaluate) in the `emails` list. Each item has a `speaker`, `AGENT` or `USER`, and `raw`, the full source of the email with all its headers. The full source is the RFC 822 text you get from **Show original** in Gmail or from your mail provider's API.

- Send the emails in thread order, oldest first.
- A request can carry up to 100 emails, and each email can be up to 1 MB.
- If you leave out `transcript`, Bluejay builds it from the emails. Each email becomes one entry, without the quoted history of earlier replies. Its time comes from the email's **Date** header, measured from `start_time_utc`, so set `start_time_utc` to the time of the first email.

```bash
curl -X POST https://api.getbluejay.ai/v1/evaluate \
  -H "X-API-Key: $BLUEJAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "agent_id": "<agent-id>",
    "start_time_utc": "2026-10-20T15:02:11Z",
    "participants": [
      { "role": "USER", "name": "Dana Reyes", "spoke_first": true },
      { "role": "AGENT", "name": "Northwind Support" }
    ],
    "metadata": { "external_conversation_id": "thread-48213" },
    "emails": [
      {
        "speaker": "USER",
        "raw": "From: Dana Reyes <dana@example.com>\r\nTo: support@northwind.example\r\nSubject: Order 10482 has not arrived\r\nDate: Tue, 20 Oct 2026 15:02:11 +0000\r\nMessage-ID: <c81f@example.com>\r\n\r\nHi, my order 10482 was due last Friday and the tracking has not moved. Can you check?\r\n"
      },
      {
        "speaker": "AGENT",
        "raw": "Return-Path: <bounce@northwind.example>\r\nAuthentication-Results: mx.example.com; spf=pass smtp.mailfrom=northwind.example; dkim=pass header.d=northwind.example; dmarc=pass header.from=northwind.example\r\nDKIM-Signature: v=1; a=rsa-sha256; d=northwind.example; s=mail; h=from:to:subject:date; bh=...; b=...\r\nFrom: Northwind Support <support@northwind.example>\r\nTo: Dana Reyes <dana@example.com>\r\nSubject: Re: Order 10482 has not arrived\r\nDate: Tue, 20 Oct 2026 15:04:37 +0000\r\nIn-Reply-To: <c81f@example.com>\r\n\r\nHi Dana, the carrier lost the parcel. I have sent a replacement, and it arrives Thursday.\r\n\r\nOn Tue, 20 Oct 2026, Dana Reyes wrote:\r\n> Hi, my order 10482 was due last Friday and the tracking has not moved.\r\n"
      }
    ]
  }'
```

## Update a thread

A thread grows after you send it. To keep one conversation for it in Bluejay, put your own id for the thread in `metadata` as `external_conversation_id`:

```json
"metadata": { "external_conversation_id": "thread-48213" }
```

When you send again with the same id, Bluejay replaces that conversation with what you send and grades it again. Always send the full thread, not only the new emails, because the new request replaces the earlier content. Bluejay ignores a request whose content is the same as what it already has. Without the id, every request creates a new conversation.

If `metadata` also carries a provider call id, such as `vapi_call_id`, Bluejay uses that id instead.

<Tip>
Every conversation you send is evaluated and billed. We suggest you send a thread once it has ended, rather than after every email.
</Tip>

## Email checks

For every email from your agent, Bluejay runs four checks: **SPF**, **DKIM**, **DMARC**, and **Spam**. The results show on the conversation and on [dashboards](/monitor/dashboards). A thread passes a check only if every agent email passes it. **Spam** shows the worst score in the thread. Expand a check to see the reason for each email.

### Where each verdict comes from

A receiving mail server records its verdicts in headers such as **Authentication-Results** when the email arrives. A copy taken from your own sent folder has no such headers, so some checks depend on where you take the copy from.

- **SPF**: only a receiving server can judge SPF, because it needs the address of the server that connected to it. Bluejay reads the verdict from the **Authentication-Results** or **Received-SPF** header. Without one, SPF shows **N/A**.
- **DKIM**: Bluejay checks the signature itself against the key the sender's domain publishes, so it works on any copy. If Bluejay's check fails but a receiving server recorded a pass, the server's pass counts. That happens when a mail gateway changes the email after the server checked it, for example by adding a footer.
- **DMARC**: Bluejay uses the receiving server's verdict when the email has one. Otherwise it checks alignment itself and looks up the domain's DMARC policy.
- **Spam**: Bluejay reads a score only from headers such as **X-Spam-Score**. Gmail and Outlook do not add a number, so **Spam** is often missing.
