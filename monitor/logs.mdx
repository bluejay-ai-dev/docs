## Get conversations into Logs

Logs shows your production conversations. They can arrive from three sources:

| Source | How conversations arrive |
|--------|--------------------------|
| Voice platform | Each ended call arrives after you [connect the platform](/integrations/vapi#monitor). |
| [`POST /v1/evaluate`](/api-reference/endpoint/evaluate) | Your backend sends each conversation after it ends. |
| **Upload** | Upload **Audio Call** files or a **Chat/Transcript** from the Logs page. |

Bluejay runs your custom metrics on each conversation when it arrives. If your organization scores only a sample of production conversations, the others show **Not Evaluated**. See [Call statuses](/test/simulations/simulation-results#call-statuses).

## Find a conversation

To find the conversations worth reading, start from a failing metric or an Issue, then read the transcript to see where the agent went wrong. You can also type a plain-text query in the search box, for example "failed calls yesterday". If a transcript does not explain the failure, open the linked [Traces](/key-concepts/traces/overview).

## Act on conversations

Select one or more conversations, then:

- **Reevaluate** runs the metrics again. If all selected conversations belong to one agent, it can use a different Agent Version, so you can check a fix on real conversations.
- **Replay** tests the conversations against a target agent in a [simulation](/test/simulations/overview), so a real failure becomes a repeatable test.
- **Add to lab** adds the conversations to a [Metrics Lab](/key-concepts/metrics-lab/overview). Use it when a metric verdict looks wrong on many conversations.
- **Edit metrics** corrects a metric result that you disagree with.
