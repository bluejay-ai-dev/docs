Use an alert to have Bluejay tell your team when a metric on your production conversations crosses a threshold you set.

To catch a slow drop in quality, watch a pass rate over many conversations. To catch a failure that must never happen, watch a single event.

To create alerts from code, use the [Alerts API](/api-reference/endpoint/create-alert).

## How alerts evaluate

An alert counts the production conversations that match the condition in a window, either a time interval or the last N conversations. The alert enters alarm when at least N conversations match, and recovers when the count drops below 80% of N (minimum 1).

With the last N conversations as the window, the alert does not fire until N conversations exist.

For a metric where one failure is too many, for example hallucination, set N to 1.

Create each alert in the [workspace](/administration/workspaces) of the agents it should watch. Even an alert set to all agents watches only its own workspace.

## Choose where each alert goes

Each alert and uptime monitor has its own channels, so you can match the channel to how urgent the problem is. Page the on-call team for failures that need action now, for example an uptime monitor that goes DOWN, and send quality drops to Slack or email. A channel stays off until you connect it.

To check the setup before you rely on it, use **Send test notification** on an alert.

## Incidents

PagerDuty and Better Stack receive incidents, and your escalation policy in that tool decides who gets the page.

| Source | Opens an incident | Resolves the incident |
|---|---|---|
| Uptime monitor | When the monitor goes DOWN | When the monitor recovers |
| Alert | When the alert triggers, in PagerDuty and Better Stack | When the alert recovers, in PagerDuty and Better Stack |
