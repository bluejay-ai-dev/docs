The Bluejay GitHub Action runs a simulation in CI and fails the step if the pass rate is below `min_score`.

## How the action works

1. It queues a run for the simulation (`POST /v1/queue-simulation-run`).
2. It polls until the run ends (`GET /v1/retrieve-simulation-results/{run_id}`).
3. It computes the score as the pass rate: `tests_passed / total_tests × 100`.
4. The step fails if the run does not complete, or if the score is below `min_score`.

## Prerequisites

1. A Bluejay API key from the [developers page](https://app.getbluejay.ai/developers).
2. An agent connected to your assistant.
3. A simulation on that agent, with the Digital Humans you want to run.

The agent in Bluejay holds the connection to your assistant. The CI workflow needs only `api_key` and `simulation_id`, for all connection types.

## Option 1: Test an existing agent

Use this option unless you have a preview deployment for each PR. You set up the agent and simulation one time, and CI refers to the simulation. All runs stay on one simulation, so you can compare them.

<Steps>
  <Step title="Add your API key and variables">
    1. In GitHub, go to **Settings > Secrets and variables > Actions**.
    2. Click **New repository secret**. Set the name to `BLUEJAY_API_KEY` and the value to your API key.
    3. Open the **Variables** tab and click **New repository variable**. Add these variables:

| Variable Name | Value | Required |
|--------------|-------|----------|
| `BLUEJAY_SIMULATION_ID` | Your simulation ID (e.g., `12345`) | Yes |
| `BLUEJAY_MIN_SCORE` | Minimum passing score (e.g., `80`) | No |
| `BLUEJAY_PROMPT_ID` | Agent Version override ID (the action input is `prompt_id`) | No |
| `BLUEJAY_KB_ID` | Knowledge base override ID | No |
| `BLUEJAY_DIGITAL_HUMAN_IDS` | Comma-separated Digital Human IDs | No |
  </Step>

  <Step title="Create your workflow">
    Add `.github/workflows/bluejay-tests.yml` to your repo:

```yaml
name: Agent Tests

on:
  workflow_dispatch:
    inputs:
      simulation_id:
        description: 'Bluejay Simulation ID to run'
        required: false
        type: string
      min_score:
        description: 'Minimum required score (0–100)'
        required: false
        type: string
        default: '80'
  push:
    branches: [main]
  pull_request:
    types: [opened, synchronize]

jobs:
  run-bluejay-tests:
    runs-on: ubuntu-latest

    steps:
      - name: Run Bluejay Tests
        uses: bluejay-ai-dev/bluejay-github-actions@v1
        with:
          api_key: ${{ secrets.BLUEJAY_API_KEY }}
          # Required: simulation id (manual input OR repo variable)
          simulation_id: ${{ inputs.simulation_id || vars.BLUEJAY_SIMULATION_ID }}
          # Optional overrides (omit the ones you do not use)
          prompt_id: ${{ vars.BLUEJAY_PROMPT_ID }}
          knowledge_base_id: ${{ vars.BLUEJAY_KB_ID }}
          digital_human_ids: ${{ vars.BLUEJAY_DIGITAL_HUMAN_IDS }}
          # Behavior controls
          wait_for_results: 'true'
          min_score: ${{ inputs.min_score || vars.BLUEJAY_MIN_SCORE || '80' }}
          poll_interval_seconds: '10'
          timeout_seconds: '1500'
```
  </Step>

  <Step title="Trigger a simulation">
    Open a pull request. The action runs the simulation on each PR.

![GitHub Action Check](/images/trigger_github_action.png)
  </Step>

  <Step title="Monitor your simulation">
    Open the **Actions** tab in your GitHub repository to see the run. The status and score show when the run ends.

![GitHub Action Monitor](/images/monitor_github_action.png)
  </Step>
</Steps>

## Option 2: Create, test, and delete

Use this option if CI makes a preview deployment for each PR. The workflow creates an agent and a simulation, runs the test, and deletes them. Your Digital Humans stay, because they are your test suite.

In the `add-agent` payload, include the connection field for your preview deployment. See [Add Agent](/api-reference/endpoint/add-agent) for the fields. Bluejay sets the connection type from the field you send.

For this option, `BLUEJAY_DIGITAL_HUMAN_IDS` is required, for example `101,102`. A new simulation has no Digital Humans, and the run fails without them.

```yaml
name: Agent Tests (ephemeral)

on:
  pull_request:
    types: [opened, synchronize]

env:
  BLUEJAY_API: https://api.getbluejay.ai/v1
  BLUEJAY_API_KEY: ${{ secrets.BLUEJAY_API_KEY }}

jobs:
  run-bluejay-tests:
    runs-on: ubuntu-latest
    steps:
      - name: Create ephemeral agent
        id: agent
        run: |
          payload=$(jq -n \
            --arg name "ci-pr-${{ github.event.number }}-run-${{ github.run_id }}" \
            --arg connection "<how Bluejay reaches this PR's preview deployment>" \
            '{
              name: $name,
              system_prompt: "Customer support assistant under test",
              knowledge_base: "",
              goals: ["Resolve the customer issue"],
              "<your connection field>": $connection
            }')
          resp=$(curl -s --fail-with-body -X POST "$BLUEJAY_API/add-agent" \
            -H "X-API-Key: $BLUEJAY_API_KEY" \
            -H "Content-Type: application/json" \
            -d "$payload")
          echo "id=$(echo "$resp" | jq -r '.agent_id')" >> "$GITHUB_OUTPUT"

      - name: Create simulation
        id: sim
        run: |
          resp=$(curl -s --fail-with-body -X POST "$BLUEJAY_API/create-simulation" \
            -H "X-API-Key: $BLUEJAY_API_KEY" \
            -H "Content-Type: application/json" \
            -d '{
              "agent_id": "${{ steps.agent.outputs.id }}",
              "name": "CI PR #${{ github.event.number }}"
            }')
          echo "id=$(echo "$resp" | jq -r '.simulation_id')" >> "$GITHUB_OUTPUT"

      - name: Attach Digital Humans
        run: |
          curl -s --fail-with-body -X POST "$BLUEJAY_API/simulation/${{ steps.sim.outputs.id }}/add-digital-humans" \
            -H "X-API-Key: $BLUEJAY_API_KEY" \
            -H "Content-Type: application/json" \
            -d '{"digital_human_ids": [${{ vars.BLUEJAY_DIGITAL_HUMAN_IDS }}]}'

      - name: Run Bluejay Tests
        uses: bluejay-ai-dev/bluejay-github-actions@v1
        with:
          api_key: ${{ secrets.BLUEJAY_API_KEY }}
          simulation_id: ${{ steps.sim.outputs.id }}
          wait_for_results: 'true'
          min_score: '80'

      - name: Clean up
        if: always()
        run: |
          status=0
          if [ -n "${{ steps.sim.outputs.id }}" ]; then
            curl -s --fail-with-body -X DELETE "$BLUEJAY_API/simulation/${{ steps.sim.outputs.id }}" \
              -H "X-API-Key: $BLUEJAY_API_KEY" || status=1
          fi
          if [ -n "${{ steps.agent.outputs.id }}" ]; then
            curl -s --fail-with-body -X DELETE "$BLUEJAY_API/agent/${{ steps.agent.outputs.id }}" \
              -H "X-API-Key: $BLUEJAY_API_KEY" || status=1
          fi
          exit $status
```

<Warning>
  The cleanup step deletes the agent and the simulation, and the run history with them. To keep results, remove the cleanup step or use Option 1.
</Warning>

## Pin to a commit SHA

If your organization requires a full-length commit SHA for third-party actions, the error is *"all actions must be pinned to a full-length commit SHA"*. A tag such as `v1` can move. A commit SHA cannot. To find the commit for `v1`, run:

```bash
git ls-remote https://github.com/bluejay-ai-dev/bluejay-github-actions 'refs/tags/v1^{}'
```

You can also open the [repository](https://github.com/bluejay-ai-dev/bluejay-github-actions), click **Tags**, and copy the commit for `v1`. Then use the SHA:

```yaml
uses: bluejay-ai-dev/bluejay-github-actions@c28260e8bd21f29e3841c712131a0ae979c7bdd7 # v1
```

The SHA above is what `v1` resolves to as of July 2026.

<Note>
  A SHA pin does not follow updates to `v1`. To get fixes, run the command again and update the pin. [Dependabot](https://docs.github.com/en/code-security/dependabot/working-with-dependabot/keeping-your-actions-up-to-date-with-dependabot) with `package-ecosystem: github-actions` can update it for you.
</Note>

## Inputs

| Input | Required | Default | Description |
|-------|----------|---------|-------------|
| `api_key` | Yes | None | Your Bluejay API key. |
| `simulation_id` | Yes | None | ID of the simulation to run. |
| `prompt_id` | No | None | Agent Version UUID to use for this run. |
| `knowledge_base_id` | No | None | Override knowledge base for this run. |
| `digital_human_ids` | No | None | Comma-separated list of Digital Human IDs. |
| `phone_number` | No | None | Phone number to use for this run. |
| `sip_uri` | No | None | SIP URI to use for this run. |
| `wait_for_results` | No | `true` | If `true`, wait for the run to end and fail CI on the score. |
| `min_score` | No | `80` | Required pass rate (0–100). |
| `poll_interval_seconds` | No | `10` | Polling frequency in seconds. |
| `timeout_seconds` | No | `1500` | Maximum wait in seconds (25 minutes). |

## Outputs

| Output | Description |
|--------|-------------|
| `simulation-run-id` | The ID of the queued simulation run. |
| `final-status` | Final run status: `completed`, `failed`, or `cancelled`. |
| `score` | Pass rate of the run: `tests_passed / total_tests × 100`. |
| `report-url` | Link to the run report, if available. |

## Triggers

Any [GitHub Actions trigger](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows) works. Change only the `on:` section. For example, to run daily at 09:00 UTC:

```yaml
on:
  schedule:
    - cron: '0 9 * * *'
```
