## A

<Columns cols={2}>

### Agent

The voice, text, or email AI system that you want Bluejay to test and monitor. Your simulations, conversations, and custom metrics all belong to an agent.

[Agents](/test/simulations/create#connect-your-agent) [API Reference](/api-reference/endpoint/add-agent)

### Agent Variables

Values that every Digital Human of an agent knows, for example a business name. A Digital Human's trait with the same name overrides one.

[Agent Variables](/test/simulations/digital-humans#agent-variables) [API Reference](/api-reference/endpoint/update-agent)

### Agent Version

A saved, numbered copy of an agent prompt. Labels such as `production` and `latest` point to a version and decide which one a run uses.

[Agent Versions](/test/simulations/reference#agent-versions) [API Reference](/api-reference/endpoint/create-prompt-version)

### Alert

A rule that notifies your team when a metric on production conversations crosses a threshold.

[Alerts](/monitor/alerts) [API Reference](/api-reference/endpoint/create-alert)

</Columns>

## B

<Columns cols={2}>

### Binary Frame

A WebSocket message that carries raw bytes instead of text. In the CHIRP protocol, binary frames carry the audio.

[WebSocket Integration](/integrations/websockets#audio)

### Bluejay AI

The assistant inside the Bluejay app. It tells you why calls failed and can make the change for you, for example create a simulation, a custom metric, or a dashboard.

[Bluejay AI](/improve/bluejay-ai)

### Bluejay as Code

Keeping your agents, simulations, Digital Humans, and custom metrics in a YAML file. You pull the file from Bluejay, edit it, and push it back, by hand or from CI.

[Bluejay as Code](/bluejay-as-code/overview) [Cookbook](/bluejay-as-code/cookbook)

</Columns>

## C

<Columns cols={2}>

### Call Status

Where a simulated call is in its life, for example Queued, Running, or Completed. A call that fails also has an error code that says why.

[Call Statuses](/test/simulations/reference#call-statuses)

### CHIRP

The protocol that Bluejay uses to exchange audio and text events with your server over a WebSocket.

[WebSocket Integration](/integrations/websockets)

### Community

A saved group of Digital Humans that you can add to any simulation, so you reuse the same test suite instead of building it again.

[Communities](/test/simulations/digital-humans#communities) [API Reference](/api-reference/endpoint/create-community)

### Composite Metric

A custom metric that combines the results of other metrics into one number or label. It does not call an LLM.

[Composite Metrics](/test/metrics/composite) [Example](/bluejay-as-code/cookbook#composite-metrics)

### Conditional Metric

A custom metric that runs only on conversations that meet a condition, for example when the agent called a given tool. On other conversations it has no result.

[Conditional Metrics](/test/metrics#add-metric-conditions) [Example](/bluejay-as-code/cookbook#conditional-metrics)

### Connection Type

How Bluejay reaches your agent to call or message it. You choose it when you add the agent, and each connection type has its own setup page under Integrations.

[Agents](/test/simulations/create#connect-your-agent) [Integrations](/integrations/phone-number)

### Conversation

One call, text thread, or email thread between an agent and a caller. It includes the transcript and the metric results.

[Logs](/monitor/logs) [API Reference](/api-reference/endpoint/list-conversations)

### Custom Metric

A rule that you write to grade each conversation. It can grade simulations, production calls, or both.

[Simulation Metrics](/test/metrics) [Production Metrics](/monitor/metrics) [API Reference](/api-reference/endpoint/create-metrics-v2)

### Customer Journeys

A simulation type in which the same Digital Human contacts your agent several times in a fixed order, to test how the agent treats a customer who comes back.

[Customer Journeys](/test/simulation-types/customer-journeys)

</Columns>

## D

<Columns cols={2}>

### Dashboard

A page of widgets that chart your metrics over time, for either simulation data or production data.

[Simulation Dashboards](/test/dashboards) [Production Dashboards](/monitor/dashboards) [API Reference](/api-reference/endpoint/create-dashboard)

### Diarization

Splitting an audio recording by speaker, so that each thing said is credited to the right person.

### Digital Human

A simulated customer that calls, texts, or emails an agent in a simulation. Each one is a test case, and it runs once as each of its personas, or once as the baseline, its own settings, when it has none. A customer journey always runs as the baseline.

[Digital Humans](/test/simulations/digital-humans) [API Reference](/api-reference/endpoint/create-digital-humans-v2)

### DTMF

The tones a phone makes when you press its keypad. A Digital Human can send them to an agent, for example to choose a menu option.

[Personas](/test/simulations/digital-humans#scripted-responses)

### Dynamic Variable

A `{{key}}` placeholder in a metric prompt. Before the judge runs, Bluejay replaces it with the value of that key in the conversation metadata.

[Dynamic Variables](/test/metrics/llm-as-a-judge#dynamic-variables)

</Columns>

## E

<Columns cols={2}>

### Error Code

The code on a failed call that says what went wrong, for example `NO_ANSWER`. Each code belongs to one failed call status, such as No Connection or System Error.

[Error Codes](/test/simulations/reference#error-codes)

### Evaluate

The API you use to send one production conversation to Bluejay, which then scores it with your custom metrics.

[Evaluate API](/api-reference/endpoint/evaluate) [Logs](/monitor/logs)

</Columns>

## F

<Columns cols={2}>

### Folder

A group of agents. A webhook can select a folder to cover all of its agents at once.

[Webhooks](/api-reference/webhooks) [API Reference](/api-reference/endpoint/create-folder)

</Columns>

## H

<Columns cols={2}>

### Hallucination

A built-in metric that checks what an agent says against the facts in its Knowledge Bases. Add it from the **Library** tab on the **Metrics** page.

[Knowledge Bases](/test/simulations/reference#knowledge-bases)

</Columns>

## I

<Columns cols={2}>

### Inbound Agent

An agent that answers conversations the customer starts. In a simulation, the Digital Human calls, texts, or emails the agent first.

[Agents](/test/simulations/create#connect-your-agent)

### Issue

A group of similar failures, or a known system error, so that you can triage them as one problem instead of one at a time. Simulations and production have separate issue lists.

[Simulation Issues](/test/issues) [Production Issues](/monitor/issues) [API Reference](/api-reference/endpoint/list-issues)

### IVR Flow

A phone menu that you draw on the **Scenario Builder** page. In the IVR Flow simulation type, the Digital Human plays the menu and your outbound agent calls through it.

[IVR Flow](/test/simulation-types/ivr-flow) [Example](/cookbook/ivr-phone-menu)

</Columns>

## K

<Columns cols={2}>

### Knowledge Base

A set of documents with the facts your agent must know. Bluejay uses it to grade the agent's answers and to generate Digital Humans.

[Knowledge Bases](/test/simulations/reference#knowledge-bases) [API Reference](/api-reference/endpoint/create-knowledge-base)

</Columns>

## L

<Columns cols={2}>

### Label

A name, for example `production`, that points to one agent version, so a run can pick a version by name.

[Agent Versions](/test/simulations/reference#agent-versions) [API Reference](/api-reference/endpoint/create-label)

### Latency

How long the agent takes to respond: the time from when the caller stops speaking to when the agent starts.

### LLM as a Judge

A type of custom metric in which an LLM reads the conversation and scores it using a prompt that you write.

[Custom Metrics](/test/metrics#metric-types) [Prompting Guide](/test/metrics/llm-as-a-judge#prompting-guide)

### Load Testing

A simulation type that runs many conversations at the same time, to test your agent's latency and throughput under load.

[Load Testing](/test/load-testing/overview)

</Columns>

## M

<Columns cols={2}>

### MCP Server

The Bluejay server that lets an AI assistant work in Bluejay for you. You ask in plain language, and the assistant creates simulations, runs them, and reads the results.

[Bluejay MCP Server](/mcp/overview)

### Metrics Lab

Where you label conversations with the verdict you expect, so that Bluejay can tune a custom metric until it agrees with you.

[Metrics Lab](/test/metrics/metrics-lab) [API Reference](/api-reference/endpoint/create-lab)

### Mono

Audio with a single channel, as opposed to stereo. The CHIRP protocol uses mono audio.

[WebSocket Integration](/integrations/websockets#audio)

</Columns>

## O

<Columns cols={2}>

### Observability

The section of the Bluejay app for your real production conversations, where custom metrics score them and you review the results in Logs. The docs cover it under Monitor.

[Logs](/monitor/logs)

### Outbound Agent

An agent that starts the conversation, for example by calling the customer. To test one, Bluejay usually calls your outbound trigger webhook, and your system then contacts the Digital Human.

[Agents](/test/simulations/create#connect-your-agent) [Phone Number](/integrations/phone-number#outbound-agents)

### Outbound Trigger Webhook

A URL on your system that Bluejay sends a POST to for each conversation in a run. Your system then calls or messages the Digital Human, so your outbound agent starts the conversation.

[Outbound Trigger Webhook](/test/simulations/reference#outbound-trigger-webhook)

</Columns>

## P

<Columns cols={2}>

### pcm_s16le

The audio encoding that the CHIRP protocol uses: signed 16-bit little-endian PCM.

[WebSocket Integration](/integrations/websockets#audio)

### Persona

A reusable caller: who calls your agent, with their personality, voice and behavior. A Digital Human runs once as each persona it lists, so one test covers several callers. Customer journeys are the exception and run as the baseline.

[Personas](/test/simulations/digital-humans#personas) [API Reference](/api-reference/endpoint/list-personas)

### Personality

A field on a Digital Human: one line that says who the caller is. It applies when the Digital Human runs as the baseline, without a persona.

[Digital Humans](/test/simulations/digital-humans)

### PSTN

The public phone network, which carries calls to regular phone numbers. It usually drops custom SIP headers.

[SIP Integration](/integrations/sip)

</Columns>

## R

<Columns cols={2}>

### Red Teaming

Tests in which adversarial Digital Humans call an agent to find out whether a caller can trick it into leaking data or saying harmful things.

[Red Teaming](/test/red-teaming/overview) [Attack Catalog](/test/red-teaming/overview#attack-catalog)

### Redundancy

A built-in metric that flags when the agent repeats itself. Add it from the **Library** tab on the **Metrics** page.

[Logs](/monitor/logs)

### Reevaluate

Scoring an existing conversation again. No new call is made.

[Logs](/monitor/logs#act-on-conversations) [API Reference](/api-reference/endpoint/re-evaluate)

### Regression Testing

Running the same simulation again after you change your agent, to catch anything that got worse before you ship.

[Simulations](/test/simulations/create)

### Response Type

The kind of result a custom metric returns, for example Pass/Fail, a number, or one label from a list.

[Response Types](/test/metrics/llm-as-a-judge#response-types)

</Columns>

## S

<Columns cols={2}>

### Sample Rate

The number of audio samples taken each second. The CHIRP protocol uses 16000 Hz.

[WebSocket Integration](/integrations/websockets#audio)

### Scenario

A conversation flow that you draw as a graph on the **Scenario Builder** page. Bluejay makes one Digital Human for each path through the graph.

[Scenario Adherence](/test/simulation-types/scenario-adherence#build-a-scenario) [API Reference](/api-reference/endpoint/create-scenario)

### Schedule

A setting that runs a simulation automatically at fixed times.

[API Reference](/api-reference/endpoint/create-schedule)

### Scripted Response

A fixed reply that a Digital Human gives when the agent says a given line, so the reply is the same on every run.

[Scripted Responses](/test/simulations/digital-humans#scripted-responses)

### Self-Improve

A run in which Bluejay finds why calls fail, rewrites the agent prompt, and keeps each change only if the simulation pass rate goes up.

[Self-Improve](/improve/self-improve) [API Reference](/api-reference/endpoint/start-self-improve-run)

### Simulation

A set of Digital Humans that test one agent. You can run the same simulation as many times as you need.

[Simulations](/test/simulations/create) [API Reference](/api-reference/endpoint/create-simulation)

### Simulation Result

The outcome of one Digital Human's conversation in a simulation run, including its transcript and scores.

[Simulation Results](/test/simulations/create#read-the-results) [API Reference](/api-reference/endpoint/retrieve-simulation-result)

### Simulation Run

One run of a simulation, in which each Digital Human has at least one conversation with the agent.

[Simulation Results](/test/simulations/create#read-the-results) [API Reference](/api-reference/endpoint/queue-simulation-run-v2)

### Simulation Type

The way a simulation makes its Digital Humans, for example from a description, a CSV file, or past conversations. Each type has its own page under Simulations.

[Create a Simulation](/test/simulations/create#pick-a-type-yourself) [Natural Language](/test/simulation-types/natural-language)

### SIP

Session Initiation Protocol, a way to connect voice systems to each other directly. SIP calls can carry headers such as `X-Simulation-Result-Id`.

[SIP Integration](/integrations/sip) [Send Tool Calls](/test/metrics#send-tool-calls)

### Success Criteria

What decides whether one Digital Human's call passes or fails: a list of things the agent should do that the transcript can show. Bluejay grades each bullet, and the call passes only when all of them pass.

[Success Criteria](/test/simulations/digital-humans#success-criteria) [Retrieve Results v2](/api-reference/endpoint/retrieve-simulation-results-v2)

</Columns>

## T

<Columns cols={2}>

### Telephony

Simulations that run over phone numbers. A Digital Human calls an inbound agent, or an outbound agent calls a Digital Human.

[Phone Number Integration](/integrations/phone-number) [SIP Integration](/integrations/sip)

### Test

The part of Bluejay for checking your agent before it reaches production, such as simulations and Red Teaming. In the app, it is the **Simulations** section.

[Simulations](/test/simulations/create)

### Test Case

One thing a caller tries to do, with the success criteria that grade the call. In Bluejay each test case is a Digital Human, listed on the **Test Cases** tab.

[Digital Humans](/test/simulations/digital-humans) [Upload CSV](/test/simulation-types/upload-digital-humans)

### Tool Calls

The functions an agent calls during a conversation, such as looking up an account. Send them to Bluejay so that custom metrics can check what the agent did, not only what it said.

[Tool Calls](/test/metrics#tool-calls-events-and-metadata)

### Trace

An OpenTelemetry record of the steps your agent took behind the scenes. When you link a trace to a conversation, Bluejay shows them side by side.

[Simulation Traces](/test/traces) [Production Traces](/monitor/traces) [API Reference](/api-reference/endpoint/list-traces)

### Traits

Facts that a Digital Human knows and gives when the agent asks, for example a member ID. You set them on each Digital Human, and each trait has the same value on every run.

[Traits](/test/simulations/digital-humans#traits)

### Transcript

The written text of a conversation, with each line marked by who said it.

[Evaluate API](/api-reference/endpoint/evaluate)

</Columns>

## U

<Columns cols={2}>

### Uptime Monitor

A test conversation that Bluejay runs with your live agent on a schedule. It notifies you when the agent goes DOWN and again when it is back UP.

[Uptime Monitoring](/monitor/uptime/overview) [API Reference](/api-reference/endpoint/create-uptime-monitor)

</Columns>

## W

<Columns cols={2}>

### Webhook

A URL on your server that Bluejay sends a signed POST request to when an event occurs, for example when a simulation ends.

[Webhooks](/api-reference/webhooks) [Events Webhook](/api-reference/webhook/events-webhook)

### Workflow

The multi-agent graph of an agent, for example a root agent that hands off to sub-agents. You can pull it from your provider, edit it, and push it back, or import one from a document. It is different from a scenario.

[Workflow](/test/simulations/reference#workflow)

</Columns>
