The Amelia integration connects your Amelia (SoundHound) bots to Bluejay. You can test them with Digital Humans over chat or voice, and import their AI agents and conversation flows.

## Connect

Amelia has no API key. To import agents and flows, Bluejay signs in with an Amelia user account. Simulations do not use this account. Go to **Settings > Integrations > Amelia**.

| Field | Value |
|---|---|
| Amelia URL | Where you sign in to Amelia, for example `https://yourcompany.amelia.com`. It must be a public `https` address. |
| Username | An Amelia account that can view your domain. |
| Password | The password of that account. Bluejay stores it encrypted. |
| Sync from Amelia | Imports each AI agent as an agent in the **Synced from Amelia** folder. Needs all three fields saved. |

<Warning>
Access risk. This is a full Amelia login. Use an account with only the access it needs.
</Warning>

On each agent, choose the **Amelia** tile in **Connection Settings**. Use the voice tile for a call or the text tile for a chat.

| Field | Value |
|---|---|
| Amelia URL | The address you open Amelia at, including the trailing `/Amelia`, for example `https://yourcompany.amelia.com/Amelia`. Without `/Amelia`, every simulation fails at start. |
| Domain | The domain code of the bot to test, for example `acme`. A domain is one bot. |
| Agent | Optional. The AI agent whose instructions and tools Sync pulls into Bluejay. It does not change which agent answers. |
| Flow | Optional. The conversation flow that each simulation starts. Leave it unset to let Amelia route. |

Amelia picks which AI agent answers and can hand over to a different agent during a conversation. To reach one agent every time, make a flow whose **Execute Cognitive Agent** block names that agent. Then set **Flow** to that flow.

## Test

Bluejay opens a conversation the same way the Amelia web chat does. No phone number is necessary. Each result links to the conversation in Amelia.

<Tabs>
<Tab title="Chat">

Bluejay sends one message at a time.

1. Choose the **Amelia** text tile and set **Amelia URL** and **Domain**.
2. Create a simulation and add Digital Humans.
3. Run the simulation.

</Tab>
<Tab title="Voice">

Bluejay streams audio in both directions in real time. Amelia does its own speech recognition and turn-taking.

1. Choose the **Amelia** voice tile and set **Amelia URL** and **Domain**.
2. Create a simulation and add Digital Humans.
3. Run the simulation.

</Tab>
</Tabs>

### Import agents and flows

**Sync from Amelia** makes one Bluejay agent for each AI agent, set up for chat. The instructions become the first prompt version. Sync refreshes agents that are already connected and skips agents that name no AI agent and no flow.

To pull one flow as a graph:

1. Set **Flow** on the agent and leave **Agent** empty. **Agent** has priority over **Flow**.
2. Save the agent.
3. In the **Workflow** tab, click **Sync**.

Sync reads the latest flow revision. **Push** sends the whole stored flow back. Amelia validates it, saves it as a new revision, and deploys it. If Amelia finds a problem, it saves nothing.

The same actions are in the API:

```bash
curl -X POST https://api.getbluejay.ai/v1/integrations/amelia/sync -H "X-API-Key: $KEY"
curl "https://api.getbluejay.ai/v1/integrations/amelia/agents?domain_code=acme" -H "X-API-Key: $KEY"
curl "https://api.getbluejay.ai/v1/integrations/amelia/flows?domain_code=acme" -H "X-API-Key: $KEY"
curl -X POST https://api.getbluejay.ai/v1/agents/<agent_id>/workflow/sync -H "X-API-Key: $KEY"
```

Set the flow with `amelia_flow_name` on [Update Agent](/api-reference/endpoint/update-agent).

## Limits

- A domain that makes each user sign in before chat is not supported.
- Amelia AI agents are read only in Bluejay. Edit them in Amelia and sync again.
- Bluejay does not edit flow nodes or branches. Edit the flow in Amelia and sync again.
- The **Workflow** tab is hidden while **Agent** is set, because an AI agent has no graph.

| Error | Cause |
|---|---|
| Amelia session error, such as HTTP 503, at start | The agent **Amelia URL** does not end in `/Amelia`. |
| `Agent has no Amelia cognitive agent name or flow name` | Neither **Agent** nor **Flow** is set. |
| `Amelia domain '...' has no cognitive agent named '...'` | The agent name does not match an agent in that domain. |
| `Amelia has no domain with code '...' visible to these credentials` | The code is wrong, or the saved account cannot see the domain. |
| `Amelia flow '...' has no revision to sync. Deploy it in Amelia first.` | The flow was never deployed. |
| `Amelia rejected the stored admin credentials` | The username or password is wrong or expired. |
| `Amelia URL must be a public host` or `must start with https://` | The URL is `localhost`, an internal name, or a private address. |
