Bluejay can also import your AI agents and conversation flows.

## Connect

Amelia has no API key, so to import agents and flows, Bluejay signs in with an Amelia user account. Simulations do not use this account, so you need it only to import. Enter it on the **Amelia** tab of the Integrations settings:

| Field | Value |
|---|---|
| Amelia URL | Where you sign in to Amelia, for example `https://yourcompany.amelia.com`. It must be a public `https` address. |
| Username | An Amelia account that can view your domain. |
| Password | The password of that account. Bluejay stores it encrypted. |

To test a bot, open the agent's **Connection Settings** and choose an **Amelia** tile: the voice tile for a call, or the text tile for a chat. Then fill in these fields:

| Field | Value |
|---|---|
| Amelia URL | The address you open Amelia at, including the trailing `/Amelia`, for example `https://yourcompany.amelia.com/Amelia`. Without `/Amelia`, every simulation fails at start. |
| Domain | The domain code of the bot to test, for example `acme`. A domain is one bot. |
| Agent | Optional. The AI agent whose instructions and tools Sync pulls into Bluejay. It does not change which agent answers. |
| Flow | Optional. The conversation flow that each simulation starts. Leave it unset to let Amelia route. |

Amelia picks which AI agent answers and can hand over to a different agent during a conversation. To reach one agent every time, make a flow whose **Execute Cognitive Agent** block names that agent. Then set **Flow** to that flow.

## Test

A simulation needs only **Amelia URL** and **Domain** on the agent, and no phone number. Test with chat first to check the bot logic, then with voice to check the call experience.

### Import agents and flows

**Sync from Amelia** makes one Bluejay agent for each AI agent, set up for chat. It signs in with the **Amelia URL**, **Username**, and **Password** from the integration settings.

To pull one flow as a graph, set **Flow** on the agent and leave **Agent** empty, because **Agent** has priority over **Flow**. Then sync from the **Workflow** tab.

**Push** sends the stored flow back. Amelia saves it as a new revision and deploys it.

In the API, use [Sync Amelia Agents](/api-reference/endpoint/sync-amelia-agents), [List Amelia Agents](/api-reference/endpoint/list-amelia-agents), [List Amelia Flows](/api-reference/endpoint/list-amelia-flows), and [Sync Agent Workflow](/api-reference/endpoint/sync-agent-workflow). Set the flow with `amelia_flow_name` on [Update Agent](/api-reference/endpoint/update-agent).

## Limits

- A domain that makes each user sign in before chat is not supported.
- Amelia AI agents are read-only in Bluejay. Edit them in Amelia and sync again.
- Bluejay does not edit flow nodes or branches. Edit the flow in Amelia and sync again.
- The **Workflow** tab is hidden while **Agent** is set, because an AI agent has no graph.
- You can run **Sync from Amelia** once per minute. It fails if Amelia returns more than 2000 AI agents.

| Error | Cause |
|---|---|
| `Amelia session failed: HTTP <code>` at start | The agent's **Amelia URL** does not end in `/Amelia`. |
| `Agent has no Amelia cognitive agent name or flow name` | Neither **Agent** nor **Flow** is set. |
| `Amelia domain '...' has no cognitive agent named '...'` | The agent name does not match an agent in that domain. |
| `Amelia has no domain with code '...' visible to these credentials` or `No Amelia domain with code '...'` | The code is wrong, or the saved account cannot see the domain. |
| `Amelia flow '...' has no revision to sync. Deploy it in Amelia first.` | The flow was never deployed. |
| `Amelia rejected the stored admin credentials` | The username or password is wrong or expired. |
| `Amelia rejected this graph: ...` on **Push** | Amelia validation found errors in the flow. Fix them and push again. |
| `Amelia URL must be a public host` or `must start with https://` | The URL is `localhost`, an internal name, or a private address. |
