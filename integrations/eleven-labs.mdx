## Connect

<Steps>
<Step title="Save the ElevenLabs keys">
In Bluejay, open the **Eleven Labs** tab of the Integrations settings and save both values:

- **ElevenLabs API Key**: an API key from **Developers > API Keys** in ElevenLabs. Bluejay uses it to sync agents, open test calls, get tool calls, and fetch the conversation behind a production trace.
- **Webhook Secret**: the HMAC secret of your ElevenLabs post-call webhook. Bluejay rejects any production call that ElevenLabs sends without a valid signature. See [Monitor](#monitor).
</Step>
<Step title="Sync the agents">
Click **Sync Agents from ElevenLabs**. Bluejay creates an Inbound Voice agent for each ElevenLabs agent in a **Synced from ElevenLabs** folder, with its prompt, workflow, and tools. To pick up changes you make in ElevenLabs, run the sync again or turn on **Autosync from ElevenLabs**.
</Step>
</Steps>

A sync never deletes an agent. If you delete an agent in ElevenLabs, its agent stays in Bluejay.

To connect one agent by hand instead of syncing, open its **Connection Settings**, choose the **ElevenLabs** tile, and set **ElevenLabs Agent ID**. To score its production calls too, see [Monitor](#monitor).

To edit a synced workflow, open the **Workflow** tab of the agent, where you can pull changes from ElevenLabs, push your edits back, and merge a branch into Main.

## Test

<Tabs>
<Tab title="Websocket">

Bluejay opens a live web call to the agent over websocket, so no phone number is necessary. The **ElevenLabs** tile is inbound only.

For a multi-agent workflow, **Generate From Workflow** makes Digital Humans for each path, so every branch of the workflow gets a test.

Simulations always use the Main branch, so merge other branches to Main before you test them.

<video controls muted playsInline preload="metadata" poster="/images/elevenlabs-sim-generate.jpg" src="/images/elevenlabs-sim-generate.mp4" aria-label="Generate Digital Humans from a synced workflow" />

</Tab>
<Tab title="Phone">

Bluejay dials the ElevenLabs phone number like a real caller. Use this path to test carrier audio, DTMF, and the real number. Tool calls are not linked to the result.

Use an Inbound Voice agent with the [Phone connection type](/test/simulations/create#connect-your-agent) and the ElevenLabs number.

</Tab>
</Tabs>

[Self-Improve](/improve/self-improve) supports agents that use the **ElevenLabs** connection type.

## Monitor

ElevenLabs sends each production call to Bluejay through a post-call webhook. The transcript, the trace, and the recording all go to the same URL and are signed with the same secret.

<Steps>
<Step title="Create the post-call webhook">
In ElevenLabs settings, find **Post-Call Webhook** and click **Select Webhook > Create Webhook**. Set the URL to `https://api.getbluejay.ai/v1/integrations/ElevenLabs`, keep **Webhook Auth Method** as **HMAC**, and click **Create**. Copy the webhook secret into **Webhook Secret** in Bluejay.
</Step>
<Step title="Choose what ElevenLabs sends">
In the post-call webhook settings, choose what ElevenLabs sends. You can set this for the whole workspace, or override it on one agent under **Security > Post Call Webhook**. Keep **Transcript** on, because Bluejay needs it to score the call. To get [traces](#traces) and [recordings](#call-audio) too, turn on **OpenTelemetry transcript payloads** and **Send audio data**.
</Step>
</Steps>

<video controls muted playsInline preload="metadata" poster="/images/elevenlabs-1-webhook.jpg" src="/images/elevenlabs-1-webhook.mp4" aria-label="Set up the ElevenLabs webhook" />

Bluejay files each call under the Bluejay agent whose **Assistant ID** is the call's ElevenLabs agent ID, and rejects calls from any other ElevenLabs agent. A sync sets the **Assistant ID** for you. For an agent you connected by hand, open its **Observability Settings**, choose **ElevenLabs**, and paste the ElevenLabs agent ID as **Assistant ID**.

For a workflow agent, Bluejay adds an event to the conversation each time the call enters a new workflow node, so you can follow the path the call took.

### Traces

With **OpenTelemetry transcript payloads** on, ElevenLabs sends each call as a trace, with a span for every user turn, agent response, and tool call. Bluejay stores the trace and shows it next to the conversation, so you can see where the time went in a call. See [Traces](/monitor/traces).

The trace has the timing of the call but not its full content, so Bluejay fetches the conversation from ElevenLabs with your **ElevenLabs API Key**. Save the key before you turn this on. The trace has no audio, so turn on **Send audio data** too if you want recordings.

### Call audio

With **Send audio data** on, ElevenLabs sends the recording as a separate webhook, and Bluejay attaches it to the conversation. You can then play the call, and metrics that listen to audio can score it. Without it, the conversation has a transcript but no recording.

Bluejay waits up to 10 seconds for the transcript and the recording to arrive, then scores the call. If the recording arrives later, Bluejay scores the call from the transcript alone and attaches the recording when it comes.

### Relay calls from your service

If your own service relays the ElevenLabs payload to Bluejay, send it with a Bluejay API key instead. A payload that your service changed no longer matches the ElevenLabs signature, so Bluejay cannot verify it with the webhook secret.

```bash
curl -X POST https://api.getbluejay.ai/v1/integrations/ElevenLabs \
  -H "X-API-Key: $BLUEJAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d @elevenlabs-post-call-body.json
```

To attach your own fields, add a top-level `metadata` object to the payload. You can then use each field in a [metric prompt](/test/metrics#prompting-guide), for example as `{{member_id}}`.

```json
{
  "type": "post_call_transcription",
  "data": { },
  "metadata": { "member_id": 124356, "clinic": "Bluejay Clinic" }
}
```

Bluejay sets these metadata keys itself and overwrites any value you send for them:

- `eleven_labs_conversation_id`
- `eleven_labs_user_id`
- `eleven_labs_agent_id`
- `organization_id`
- `call_duration_secs`
- `termination_reason`
- `cost`
- `main_language`
- `original_webhook_data`

## Limits

| Symptom | Cause |
|---|---|
| Run fails with a missing integration error | No API key is saved. Bluejay needs the key at run time. |
| **No Connection** with <Code>CUSTOMER_CONCURRENCY_LIMIT</Code> | The run is over the concurrency of your ElevenLabs plan. Lower the max concurrency in Bluejay. |
| Edits do not show in the call | The edits are on a branch other than Main. |
| **No Connection** with <Code>ELEVEN_LABS_AUTH_FAILED</Code>, <Code>MISSING_ELEVEN_LABS_INTEGRATION</Code>, or <Code>MISSING_ELEVEN_LABS_AGENT_ID</Code> | The key is rejected, no key is saved, or the agent has no **ElevenLabs Agent ID**. |
| **No Connection** with <Code>ELEVEN_LABS_BRIDGE_CONNECT_FAILED</Code> or <Code>ELEVEN_LABS_SESSION_SETUP_FAILED</Code> | ElevenLabs accepted the connection but did not start a session. Run the call again. |
| **Call Dropped** with <Code>ELEVEN_LABS_AGENT_ERROR</Code>, <Code>ELEVEN_LABS_AGENT_START_FAILED</Code>, or <Code>ELEVEN_LABS_MONITORING_ERROR</Code> | The agent reported an error, did not start its turn, or Bluejay lost the monitoring connection. |
| Tool calls missing or partial | Bluejay gets them after the call. Long calls can return partial results. |
| Live calls do not show | The **Webhook Secret** is missing or wrong, or no Bluejay agent has the call's ElevenLabs agent ID as its **Assistant ID**. |
| Live calls do not show with **OpenTelemetry transcript payloads** on | No **ElevenLabs API Key** is saved, so Bluejay cannot fetch the conversation behind the trace. |
| Live calls have no recording | **Send audio data** is off in ElevenLabs. |
