## Connect

<Steps>
<Step title="Set up the Google credential">
Set up the **Google Agents** credential as described in [Dialogflow CX](/integrations/google-dfcx#connect). CES uses the same credential. For keyless access, run the setup script with `--ces`, which grants the sync and run roles.
</Step>
<Step title="Grant the CES roles">
Give the service account the roles in the table below. The setup script does not grant the push and publish roles, so add them yourself if you edit agents from Bluejay or use Self-Improve. Then turn on the `ces.googleapis.com` API in the project.
</Step>
<Step title="Sync the agents">
Click **Sync Agents from Google**. It creates one agent for each deployment of each CES app.
</Step>
</Steps>

| Use | Permissions | Predefined role |
|---|---|---|
| Sync and pull | `ces.apps.get`, `ces.apps.list`, `ces.agents.list`, `ces.tools.list`, `ces.appVersions.get`, <Code>ces.appVersions.list</Code>, `ces.deployments.get`, <Code>ces.deployments.list</Code> | <Code>roles/ces.viewer</Code> |
| Run simulations | <Code>ces.sessions.runSession</Code>, <Code>ces.sessions.bidiRunSession</Code> | <Code>roles/ces.client</Code> |
| Push | `ces.agents.update`, `ces.tools.update` | <Code>roles/ces.agentEditor</Code>, <Code>roles/ces.toolsEditor</Code> |
| Publish and Self-Improve | `ces.agents.update`, <Code>ces.appVersions.create</Code>, <Code>ces.deployments.update</Code> | <Code>roles/ces.agentEditor</Code>, <Code>roles/ces.appEditor</Code>, <Code>roles/ces.deploymentEditor</Code> |
| Quota | <Code>serviceusage.services.use</Code> | <Code>roles/serviceusage.serviceUsageConsumer</Code> |

`roles/ces.toolsEditor` is needed only to change a tool's description. `roles/ces.admin` covers every CES permission in the table, if you prefer one role.

To connect one agent by hand instead of syncing, give it the **Google CES** connection type and set:

| Field | Value |
|---|---|
| CES Deployment Path | <Code>{"apps/<app>/deployments/<deployment>"}</Code>. In CX Agent Studio, open **Deployed channels** and copy the **Deployment ID**. |

### What the sync pulls in

A sync reads the app version that the deployment serves. The agent's prompt in Bluejay holds every CES agent's instructions, tools, and handoffs, and a later sync updates it.

A sync never replaces a workflow that has edits you have not pushed yet.

### Edit an agent

<Steps>
  <Step title="Pull a version">
    On the synced agent's **Workflow** tab, pull the version you want to start from: the one the deployment serves, the CES draft, or any saved version.
  </Step>
  <Step title="Edit and push">
    Change an agent's name, instructions, tools, or handoffs, then push. A push always goes to the CES draft, so callers do not hear your edits yet.
  </Step>
  <Step title="Publish">
    Publish saves the draft as a new CES version and points the deployment you choose at it. Callers hear your edits from then on.
  </Step>
</Steps>

- To add or remove an agent, or change the root agent, do it in CES and pull again. Bluejay rejects a push that does.
- If someone changed the same field in CES after your pull, the push fails and names the agent and field. Pull again and redo those edits.

## Test

You can test each synced agent by voice or by chat. The connection type you choose decides which.

<Tabs>
<Tab title="Voice">

Choose the **Google CES** voice tile. Bluejay streams audio between the Digital Human and the agent in real time, so no phone number is necessary. This path is inbound only.

</Tab>
<Tab title="Chat">

Set the agent mode to **Text** and choose the **Google CES** text tile. Bluejay sends text turns to the agent.

</Tab>
</Tabs>

## Self-Improve

[Self-Improve](/improve/self-improve) works with the **Google CES** connection type. Each round rewrites the instructions for agents in your CES app. Tools and handoffs stay as you configured them.

A CES deployment serves a published version. After each round, Self-Improve saves the new instructions as a CES version and updates the deployment to use it. When the run finishes, the deployment points at the best instructions from the run.

Each deployment syncs to its own Bluejay agent. Start Self-Improve on the Bluejay agent for a deployment you use for testing.

If the CES draft has unpublished changes, the run fails immediately. Publish or discard those changes in CES before you start.

## Limits

- Bluejay always replies `{"status": "ok"}` to client-side tool calls. You cannot set a different tool response.
- Without `serviceusage.services.use`, each voice run fails with `USER_PROJECT_DENIED`.
