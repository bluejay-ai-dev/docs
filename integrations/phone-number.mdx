If your customers reach your agent by calling or texting a phone number, connect the agent to Bluejay with that number. Digital Humans then call or text the same number your customers use, so the test goes over the real carrier path.

## Voice calls

To test an agent that answers calls, create an Inbound Voice agent with the **Phone** connection type and enter **Your Agent's Phone Number** in E.164 format, for example `+15551234567`. When a run starts, each Digital Human calls that number, and Bluejay records the call, transcribes it, and grades it.

A phone call cannot carry the result ID that links tool calls and traces to the result, because the public phone network usually drops custom SIP headers. If you need that link, connect the agent over [SIP](/integrations/sip) or through your voice platform's integration page.

## SMS

To test an agent that answers text messages, create a Text agent with the **SMS** connection type. Each Digital Human texts the agent's phone number, and Bluejay grades the run from the transcript. To start an SMS run from the API, use [Queue SMS Simulation Run](/api-reference/endpoint/queue-sms-simulation-run).

If a voice agent sends an SMS after the call, Bluejay can grade that message too. See [Follow-up SMS](/test/simulations/digital-humans#follow-up-sms).

## Outbound agents

If your agent places calls, create the agent with type **Outbound** and give each Digital Human a phone number. The Digital Humans wait on their lines until your agent calls or the run times out, so your agent needs to know when a run starts and which numbers to call. Use one of these two triggers:

- **Outbound Trigger Webhook URL** on the agent. Bluejay sends one `POST` for each conversation, and your system then calls or messages the Digital Human. See [Outbound trigger webhook](/test/simulations/create#connect-your-agent) for the body, headers, and retries.
- **`outbound_simulation_started` event** on a [webhook](/api-reference/webhooks). Bluejay sends one event per run with every number to call. The [event payload](/api-reference/webhook/events-webhook) lists the numbers.

## Digital Human numbers

Each Digital Human calls or texts from its own number, which you set on the **Connection** tab of the Digital Human. It must be a number that your organization owns. To list the numbers your organization owns, use [Get Phone Numbers](/api-reference/endpoint/phone-numbers), or ask your AI assistant through the [workspace MCP tools](/mcp/workspace-tools#phone-numbers), which can also buy and release numbers. See [Connection](/test/simulations/digital-humans#connection) for the other fields on that tab.

## Example

Say your support line is an inbound voice agent at `+15551234567`, and you want to test it before you ship a prompt change.

<Steps>
<Step title="Create the agent">
Create an Inbound Voice agent with the **Phone** connection type, and enter `+15551234567` in **Your Agent's Phone Number**.
</Step>
<Step title="Create a simulation">
Create a simulation for the agent and add Digital Humans to it. See [Create a Simulation](/test/simulations/create).
</Step>
<Step title="Run the simulation">
Each Digital Human calls `+15551234567` from its own number and talks to your agent as a customer would.
</Step>
<Step title="Read the results">
Bluejay records, transcribes, and grades each call against your success criteria and custom metrics. See [Simulation Results](/test/simulations/simulation-results).
</Step>
</Steps>

## Limits

If a call fails to connect because the number is not valid or the caller ID is not verified, the result shows `INVALID_PHONE_NUMBER` or `UNUSABLE_CALLER_ID`. If a newer simulation reuses a Digital Human's number while a test is running, Bluejay stops the older test with `SIP_TRUNK_RECYCLED`. See [Error codes](/test/simulations/simulation-results#error-codes) for what to do.
