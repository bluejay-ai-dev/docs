## Connect a channel

<Tabs>
<Tab title="Slack">
Connect Slack on the **Slack** tab of the Integrations settings and approve the permissions in Slack. Each alert then picks its own Slack channel.

![Connect to Slack](/images/integrations-slack-connect.png)
</Tab>
<Tab title="PagerDuty">
1. In PagerDuty, open the service that receives Bluejay incidents.
2. Under **Integrations**, add an **Events API V2** integration.
3. Copy the **Integration Key**.
4. In Bluejay, paste the key into **Routing Key** on the **PagerDuty** tab of the Integrations settings.
</Tab>
<Tab title="Better Stack">
1. In Better Stack, open **API tokens**, then **Team-based tokens**.
2. Select the team whose on-call rotation receives Bluejay incidents.
3. Under **Uptime API tokens**, create a token and copy it.
4. In Bluejay, paste the token into **API token** on the **Better Stack** tab of the Integrations settings. Bluejay checks the token with Better Stack when you save it.
</Tab>
<Tab title="Email">
Email needs no connection. Send to all team members, or to the addresses you enter.
</Tab>
</Tabs>

To send alerts to your own endpoint, subscribe a [webhook](/key-concepts/webhooks/overview) to the alert events.

## Choose where each alert goes

Each alert and uptime monitor has its own channels. Page the on-call team for failures that need action now, for example an uptime monitor that goes DOWN. Send quality drops to Slack or email. A channel stays off until you connect it. Use **Send test notification** on an observability alert to check the setup before you rely on it.

In the API, each entry in `notification_channels` has a `type` and a `target`. The `target` depends on the `type`:

- `email`: the email address
- `slack`: the Slack channel ID
- `webhook`: the webhook URL
- `pagerduty`: the PagerDuty routing key
- `betterstack`: Bluejay ignores `target` and uses the connected API token

![Slack Notifications in the alert dialog](/images/integrations-slack-alarm-dialog.png)

## Incidents

PagerDuty and Better Stack receive incidents. Your escalation policy in that tool decides who gets the page.

| Source | Opens an incident | Resolves the incident |
|---|---|---|
| Uptime monitor | When the monitor goes DOWN | When the monitor recovers |
| Observability alert | PagerDuty only, when the alert triggers | When the alert recovers |
| Simulation alert | One incident per run | Never. Resolve it in PagerDuty or Better Stack. |
